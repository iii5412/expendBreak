# SMS 가져오기 개선 PRD — 앱 실행 시 신규 문자 확인

- 작성일: 2026-09-10
- 상태: 핵심 범위 구현 완료 · 실제 기기 SMS 검증 대기
- 대상: Android 앱의 SMS 설정, 앱 실행·복귀 흐름, 지출 후보 검토
- 핵심 목표: **앱이 꺼져 있을 때 도착한 결제 문자도 다음 실행 시 찾아서, 사용자가 확인한 건만 지출로 등록한다.**

## 1. 사용자 문제와 제품 결정

사용자는 SMS 기능과 관련 권한을 허용했지만 실제로 지출 후보를 받아본 적이 없다. 현재 화면만으로는 문자가 없었던 것인지, 수신을 놓쳤는지, 분석에 실패했는지 알기 어렵다.

앱 실행·복귀 시 Android 문자함에서 기준 시점 이후의 SMS를 조회하는 경로를 추가한다. 실시간 수신은 빠른 후보 표시를 위한 보조 경로로 유지하고, 문자함 조회로 누락을 보완한다. 기기를 계속 켜 두거나 앱을 메모리에 유지하는 일을 사용자에게 요구하지 않는다.

제품의 기본 흐름은 다음과 같다.

```text
이번 업데이트 설치 → 변경된 읽기 범위 확인 및 권한 허용
  → 앱을 사용하지 않는 동안 결제 SMS 도착
  → 다음 앱 실행·잠금 해제 시 문자함 확인
  → “문자에서 찾은 결제 3건을 지출로 등록할까요?”
  → 사용자 검토·수정 → 선택한 지출만 등록
```

이 문서는 기존 SMS 기능의 ‘수신 이벤트만 처리’와 ‘기존 문자함을 읽지 않음’ 정책을 변경하는 제안이다. 승인 전에는 거래를 생성하지 않는 원칙은 유지한다.

## 2. 현재 코드에서 확인한 사실

| 현재 구현 | 이번 요구사항에 미치는 영향 |
|---|---|
| `AndroidManifest.xml`은 `RECEIVE_SMS`와 `SmsReceiver`를 선언한다. `READ_SMS`는 없다. | 문자함을 조회하는 권한과 구현을 추가해야 한다. |
| `SmsReceiver.kt`는 수신 문자를 `SmsQueueStore`에 전달한다. | 앱 화면이 떠 있을 때만 받도록 작성된 구조는 아니다. |
| `SmsQueueStore.kt`는 SharedPreferences에 후보를 최대 100건·7일 보관한다. | 메모리 외 저장은 이미 있지만 수신하지 못한 문자, 오래되거나 밀려난 후보를 복구할 수 없다. |
| `App.tsx`와 `smsImport.ts`는 초기 준비 완료 및 앱 복귀 시 `readPendingSms()`를 호출한다. | 실행 시 처리는 이미 존재한다. 실제 문자함 조회가 빠져 있다. |
| 네이티브 필터와 JS 파서는 승인·취소·원화 금액 등의 표현을 검사한다. | 문자 형식 때문에 후보가 안 나왔을 가능성도 별도로 검증해야 한다. |
| `SmsReviewCard.tsx`는 등록 승인·후보 제외를 제공한다. | 후보 검토를 확장하되 사용자가 승인하는 기존 흐름을 재사용한다. |
| 설정 안내는 ‘기존 문자함은 읽지 않음’이라고 명시한다. | 기존 동의를 문자함 조회 동의로 간주할 수 없다. 안내와 동의 버전을 갱신한다. |
| 제외는 큐에서 제거하고, 최근 수신 ID는 500개만 보관한다. | 문자함 재조회에서도 제외가 유지되는 별도 처리 이력이 필요하다. |

**현재 장애 원인은 미확정이다.** 메모리 상주 여부만으로 단정하지 않는다. Android는 `SMS_RECEIVED_ACTION`을 일부 암시적 브로드캐스트 제한의 예외로 문서화하고 있다. 실제 기기의 권한·활성 계정·수신 이벤트·필터 통과 여부를 구분해서 검증한다. [Android 브로드캐스트 예외](https://developer.android.com/develop/background-work/background-tasks/broadcasts/broadcast-exceptions)

## 3. 범위

### 포함

- Android 문자함의 수신 SMS 조회: 앱 실행, 포그라운드 복귀, 사용자의 `지금 확인`.
- 업데이트 기준 시점 이후에 도착한 카드 승인·체크카드 사용·승인취소 후보.
- 기기 내 분석, 후보 영속 저장, 등록 전 수정·승인·제외·나중에 확인.
- 실시간 수신과 문자함 조회 사이의 중복 제거.
- 조회 기준, 마지막 확인 시각, 결과·실패 이유 표시.
- 기존 사용자 동의 전환 및 권한 거부·회수·계정 전환 처리.

### 제외

- 사용자 확인 없는 자동 지출 등록.
- 업데이트 이전의 과거 문자 전체 가져오기와 임의 기간 선택.
- RCS, MMS/LMS, 카드사 앱 푸시, 카카오톡 알림, iOS 문자함 연동.
- 은행 입출금·자동이체·카드 청구 안내를 일반 소비로 변환하는 기능.
- 해외 통화 환산, 부분취소 자동 반영, 문자 원문을 서버·AI로 보내는 분석.
- 상시 실행 서비스나 배터리 최적화 해제를 필수로 요구하는 방식.

문자 앱에서 보이는 메시지라도 일반 SMS가 아닐 수 있다. 지원 대상 밖의 메시지를 ‘SMS 정상 조회’로 가져올 수 있다고 안내하지 않는다.

## 4. ‘업데이트 시점 이후’의 정의

### 4.1 기본 기준

‘업데이트 시점’은 **이 기능을 지원하는 APK를 해당 기기에 설치한 시각**이다. 배포 공지 시각, 앱 최초 실행 시각, 문자 본문에 적힌 결제 시각과 구분한다.

- 첫 전환 시 Android `PackageInfo.lastUpdateTime`을 읽어 기기별 `featureBaselineAt`으로 한 번 저장한다. 이 값은 패키지의 마지막 업데이트 시각이다. [PackageInfo](https://developer.android.com/reference/android/content/pm/PackageInfo#lastUpdateTime)
- 이후 일반 업데이트가 있어도 저장된 기준과 진행 위치를 초기화하지 않는다.
- 기능 도입 버전을 실행하지 않은 채 다음 버전을 설치해 최초 도입 설치 시각을 확보하지 못했다면, 확인 가능한 현재 설치 시각을 기준으로 사용하고 설정에 실제 날짜를 표시한다. 더 이른 시각을 추정하지 않는다.
- 설치 시각을 읽지 못하면 최초 전환 실행 시각을 저장하고 `이 기기에서 설정한 시점 이후`로 안내한다.
- 조회 대상은 수신 시각이 기준 이상인 SMS다. 지출 기록 날짜는 문자에서 확인한 실제 사용 날짜를 우선한다. Android SMS의 `DATE`는 수신 시각으로 정의된다. [Telephony.Sms](https://developer.android.com/reference/android/provider/Telephony.Sms)

### 4.2 사용자 상태별 적용

| 사용자 상태 | 조회 시작점과 동작 |
|---|---|
| 기존 SMS 기능이 켜져 있음 | 변경 안내에 동의하고 읽기 권한이 확인되면 업데이트 기준부터 가져온다. 업데이트와 동의 사이에 도착한 문자도 포함한다고 안내한다. |
| 기존 기능이 꺼져 있음 / 신규 설치 후 처음 켬 | 기능을 켜고 읽기 범위에 동의한 시각부터 시작한다. 업데이트 후라도 켜기 이전 문자는 자동 조회하지 않는다. |
| 기존 사용자가 변경 안내를 나중에 확인 | 문자함 조회는 시작하지 않는다. 기존 수신 기능은 기존 동의 범위에서 유지하고 설정에 `문자함 확인 설정 필요`를 표시한다. |
| 사용자가 기능을 껐다가 다시 켬 | 끈 동안의 문자는 제외한다. 다시 켠 시각으로 새 활성 구간을 시작하고 이전 등록·제외 이력은 유지한다. |
| OS에서 읽기 권한만 회수됨 | 조회를 멈추고 진행 위치를 보존한다. 기능을 끄지 않았다면 권한 복구 후 마지막 완료 지점부터 확인한다. |
| 데이터 삭제 / 재설치 | 이 기기의 동의와 기준을 새로 설정한다. 과거 제외 이력이 복원된다고 보장하지 않는다. 기존 등록 거래와의 중복 검사는 수행한다. |

예: 9/10 14:00 업데이트, 15:00 결제 SMS, 18:00 첫 실행·변경 동의라면 15:00 문자를 후보로 제시한다. 13:59 문자는 조회하지 않는다. 이후 9/12 일반 업데이트를 설치해도 9/10 기준을 유지한다.

### 4.3 기존 후보의 전환

- 이미 승인한 지출은 그대로 유지한다.
- 이전 수신 경로에서 생성한 미처리 후보는 별도로 보존하고 `이전 수신 후보`로 구분한다. 업데이트 전 문자함을 새로 읽어서 보충하지 않는다.
- 기존 큐 ID·거래 지문을 새 처리 이력과 연결해 두 경로의 동일 문자를 한 후보로 합친다.
- 이미 소실된 오래된 제외 이력은 복원할 수 없다. 전환 테스트에서 이 한계를 확인하고 기존 500개 ID만으로 영구 중복 제거가 된다고 가정하지 않는다.

## 5. 사용자 경험

### 5.1 기존 사용자에게 한 번 보여주는 변경 안내

```text
앱이 꺼져 있을 때 온 결제 문자도 확인할 수 있어요

앱을 열면 2026.09.10 14:00 이후 받은 SMS를 기기에서 확인합니다.
업데이트 후 지금까지 받은 문자도 포함합니다.
결제 내역을 찾으면 등록할지 먼저 물어봅니다.
문자 원문은 서버나 AI로 보내지 않습니다.

[문자 확인 사용하기]  [나중에]
```

- 안내 동의 후 필요한 Android 권한을 요청한다. 이전 `RECEIVE_SMS` 허용만 보고 읽기까지 허용된 것으로 처리하지 않는다.
- OS에서 이미 권한을 허용한 상태여도 변경된 읽기 범위의 앱 내 동의는 받는다.
- 거절해도 앱의 다른 기능을 사용할 수 있다. 앱을 열 때마다 권한 팝업을 반복하지 않는다.
- 새 안내는 날짜 범위의 SMS 본문을 기기에서 검사한다는 점을 정확히 설명한다. ‘금융 문자만 읽는다’는 표현으로 OS 조회 범위를 축소해서 설명하지 않는다.

### 5.2 실행·복귀 시 확인

1. 앱 인증·잠금 해제와 활성 계정 데이터 준비를 완료한다.
2. 기능 상태, 변경 안내 동의, `READ_SMS` 권한을 확인한다.
3. 마지막 완료 지점 이후의 SMS를 확인하고 기존 후보와 합친다.
4. 새 후보가 있으면 홈에 등록 질문과 검토 진입 버튼을 표시한다.
5. 사용자가 다른 작업 중이면 홈 배지로 알리고 입력 화면을 가로막지 않는다.

```text
문자에서 찾은 결제 3건을 지출로 등록할까요?
아직 지출에 반영되지 않았어요.
[내역 확인] [나중에]
```

후보가 없으면 팝업을 띄우지 않는다. `나중에` 또는 화면 닫기는 제외와 다르며 후보를 보존한다. 동일 후보에 대한 알림 표시 여부를 기기에 저장해 앱을 다시 열 때마다 같은 토스트를 반복하지 않는다. 홈의 대기 건수와 검토 진입은 계속 제공한다.

### 5.3 후보 검토

```text
문자에서 찾은 결제                     확인 대기 3건

□ 스타벅스 강남점                         5,500원
  9/10 15:00 · 신한카드 1234 · 식비        [수정]
□ 편의점                                 3,200원
  9/10 16:20 · 카드 확인 필요             [수정]

[선택한 1건 등록]  [선택 제외]  [나중에]
```

- 선택은 기본 해제 상태다. 정상 후보만 `등록 가능한 항목 모두 선택`으로 묶어서 선택할 수 있다.
- 금액·사용처·사용 시각·카드·카테고리를 검토하고 수정한 뒤 등록한다.
- 카드가 모호하면 임의의 유일한 카드로 연결하지 않는다. 카드 선택 또는 사용자의 명시적인 `카드 미연결로 기록` 확인을 요구한다.
- 금액·날짜처럼 필수 정보가 불명확하면 `확인 필요`로 남기고 일괄 등록에서 제외한다.
- 등록 성공한 후보만 목록에서 제거한다. 실패한 항목은 선택과 수정 내용을 유지한다.
- `제외`는 해당 문자를 다시 묻지 않는 결정이다. 기능 활성 구간이 유효한 동안 처리 이력을 보존한다.
- 승인취소는 별도 구역에서 연결 대상 거래와 취소 금액을 보여준 뒤 `취소 반영`으로 확인한다. 지출 일괄 등록에 섞지 않는다.

### 5.4 설정과 동작 확인

설정 이름은 `문자에서 지출 찾기`, 설명은 `앱을 열면 새 결제 문자를 확인하고 등록 여부를 물어봅니다`로 변경한다. 거래 내역의 `SMS 자동` 표시는 승인 방식에 맞게 `SMS` 또는 `문자에서 등록`으로 정리한다.

설정에 다음 정보를 제공한다.

- 켜짐/꺼짐, 문자함 읽기 권한 상태, 실시간 수신 권한 상태.
- 확인 대상 시작 일시, 마지막 확인 시도와 마지막 성공 시각.
- 이번 조회의 검사 SMS 수, 새 후보 수, 처리된 중복 수, 확인 필요 수.
- `지금 확인` 버튼과 실패 시 `다시 시도` 또는 `앱 설정`.

빈 결과도 구분한다: `새 SMS가 없습니다`, `SMS 4건을 확인했지만 지원하는 결제 내역을 찾지 못했습니다`, `문자 읽기 권한이 필요합니다`, `문자를 확인하지 못했습니다`.

금융 문자로 보이지만 파싱이 실패한 건은 `형식 확인 필요 N건`으로 따로 집계한다. 원문을 자동 수집하는 대신 사용자가 원할 때 기기 내 상세에서 직접 확인·입력할 수 있게 한다.

## 6. 조회와 저장 요구사항

### 6.1 조회 경로

- Kotlin 브리지에 문자함 조회 API를 추가하고 `ContentResolver`로 수신함을 읽는다. 필요한 열은 메시지 ID, 발신자, 본문, 수신 시각 및 제공되는 경우 SIM 식별 정보로 제한한다.
- 읽음/안 읽음 여부는 필터 조건으로 사용하지 않는다. 이미 문자 앱에서 읽은 결제 SMS도 대상이다.
- 조회는 백그라운드 작업에서 페이지 단위로 수행한다. 초기 페이지 크기는 200건으로 제안하며 기기 검증 후 조정한다.
- 문자함을 수정·삭제하거나 읽음 상태로 변경하지 않는다.
- 실시간 수신과 문자함 조회는 같은 분석·중복 판정 규칙으로 수렴한다. 두 곳의 정규식이 서로 다른 후보를 버리지 않게 회귀 사례를 공유한다.
- 기능이 활성화된 동안 7일을 넘겨 앱을 열지 않아도 미조회 기간을 임의로 버리지 않는다. 현재 100건·7일 제한을 새 후보 저장소에 그대로 적용하지 않는다.

### 6.2 진행 위치와 재시도

- 기기·계정별 활성 구간, 성공한 조회 범위, 페이지 진행 위치를 저장한다. 조회 시작 자체를 성공으로 기록하지 않는다.
- 수신 시각과 메시지 ID를 함께 사용해 동일 밀리초의 여러 SMS를 빠짐없이 처리한다.
- 페이지의 후보와 처리 이력이 영속 저장된 다음 진행 위치를 전진시킨다. 앱 종료·저장 실패 시 마지막 완료 페이지부터 재시도한다.
- 실행 중에는 조회 상한 시각을 고정한다. 그 이후 도착한 문자는 다음 조회 대상으로 남긴다.
- 문자함 저장 지연에 대비해 다음 조회에서 직전 완료 시점 전 24시간을 중첩 확인하되 활성 구간 시작보다 앞은 읽지 않는다. `지금 확인`은 활성 구간 전체를 재검사해 더 늦게 나타난 문자도 복구하고, 처리 이력으로 재표시를 막는다.
- 자동 복귀 조회는 마지막 성공 후 30초 이내면 생략할 수 있다. 수동 확인과 새 수신 신호는 이 제한을 적용하지 않는다.
- 동시 요청은 하나만 실행하고 추가 요청을 한 번 재실행하도록 병합한다.
- 읽기 권한 회수, 기기 시각 역행, 조회 오류, 저장 공간 부족을 정상적인 ‘0건’으로 처리하지 않는다. 시각 역행 시 진행 위치를 미래로 옮기지 않고 재검사 대상으로 둔다.

### 6.3 중복 및 사용자 결정 보존

- 메시지 출처 식별자와 거래 식별자를 분리한다. 같은 SMS의 두 수집 경로는 합치되 실제로 별개인 결제를 금액·분 단위 시각만으로 합치지 않는다.
- 수신 경로와 문자함의 시각이 다를 수 있으므로 동일 발신자·본문·가까운 수신 시각 및 가능한 식별 정보를 함께 비교한다. 불확실하면 검토 대상으로 남긴다.
- 현재 32비트 거래 지문과 분 단위 수신 해시를 그대로 영구 키로 채택하지 않는다. 충돌·동일 금액 연속 결제·승인번호 재사용을 검증한 버전 있는 식별 규칙을 적용하고 기존 지문과 호환한다.
- 등록·제외·취소 반영 이력은 후보 원문을 지워도 남긴다. 승인한 거래를 나중에 삭제해도 그 SMS를 자동으로 다시 등록 후보로 만들지 않는다.
- 기존 수동·영수증·음성 거래와 날짜·금액·사용처가 유사하면 `이미 기록했을 수 있어요`로 보여준다. 자동으로 지우거나 확정 중복 처리하지 않는다.
- 현재 화면에 로드한 급여 주기의 거래만으로 중복 검사를 끝내지 않는다. 후보 날짜에 해당하는 기존 거래 또는 전체 가져오기 식별 인덱스를 조회한다.
- 거래 생성에는 재시도해도 같은 거래를 가리키는 키를 사용한다. 연속 탭, 저장 후 앱 종료, 동기화 재시도에도 1건만 생성한다.
- 로컬 저장과 서버 반영을 구분한다. 오프라인 승인 시 영속적인 동기화 대기가 확보된 경우만 `기기에 저장 · 동기화 대기`로 표시하며, 확보할 수 없으면 후보를 유지한다.

### 6.4 승인과 취소가 함께 발견될 때

- 승인·취소가 모두 미등록 후보라면 연결 관계를 보여주고 한 번의 사용자 확인으로 양쪽을 처리 완료할 수 있다. 지출을 만들었다가 다시 지우는 조작을 강요하지 않는다.
- 이미 등록된 거래의 전액 취소는 연결 대상이 유일하게 확인될 때만 사용자 확인 후 반영한다.
- 부분취소, 복수의 가능한 원거래, 수동 기록과의 관계가 불명확한 경우에는 자동 삭제하지 않는다. 거래 확인으로 연결한다.
- 기준 이전 승인의 취소만 기준 이후 도착했다면 취소 후보는 표시할 수 있지만 과거 문자함 조회로 원승인을 찾지는 않는다. 기존 거래에 연결할 수 있는지만 확인한다.
- 카드 소비 승인만 소비로 기록한다. 카드 청구·대금 납부를 다시 지출로 더하지 않고, 할부는 기존 카드·청구 산식과 연결해 총액과 회차를 중복 반영하지 않는다.

## 7. 권한, 계정과 데이터

`READ_SMS`를 manifest와 Capacitor 권한 선언에 추가하고 실제 허용 상태를 개별 확인한다. 이 권한은 SMS 읽기에 필요하며 설치 경로의 허용 정책에도 영향을 받는 제한 권한이므로, 현재 APK 업데이트 경로에서 실제 허용·조회까지 확인한다. [Android READ_SMS](https://developer.android.com/reference/android/Manifest.permission#READ_SMS)

- `READ_SMS`만 허용돼도 실행 시 조회는 가능해야 한다. `RECEIVE_SMS`가 없다는 이유로 전체 기능을 차단하지 않는다.
- `RECEIVE_SMS`만 허용된 기존 사용자는 `수신 문자만 확인 중`으로 표시하고 문자함 보완이 작동한다고 표현하지 않는다.
- 앱 내 동의는 버전과 시각을 기록한다. OS 권한과 기기 활성 상태는 동기화된 계정 토글만 보고 추정하지 않는다.
- 문자함 조회는 로그인·잠금 해제 후 활성 계정에 한정한다. 조회 도중 잠금·로그아웃·계정 전환 시 이전 작업 결과를 새 계정에 반영하지 않는다.
- 같은 기기에서는 문자 수집 담당 계정을 하나만 둔다. 계정 전환으로 새 계정에 과거 문자 범위를 자동 승계하지 않는다. 재활성화 시 새 구간을 시작하고, 이전 계정의 후보는 그 계정에서만 접근한다.
- 일반 화면 잠금은 기능 끄기와 구분한다. 잠금 중 새 문자는 다음 해제 시 확인한다. `wipeCacheOnLock` 사용 시에는 원문·후보 캐시를 지우되 재확인 기준과 최소 처리 키를 보존할 수 있는지 기존 삭제 정책과 함께 구현 검토한다. 전체 SMS 로컬 상태 삭제를 선택한 경우에는 삭제 사실을 안내하고 새 활성 구간부터 시작한다.
- 원문은 기기 안에서만 처리한다. 일반 문자는 분석 후 보관하지 않는다. 정상 후보는 구조화된 필드 위주로 저장하고 원문은 상세 확인 때 권한 내에서 다시 읽는다.
- 파싱 실패 원문도 별도 파일·로그에 남기지 않는다. 필요한 경우 메시지 식별자와 실패 분류만 저장한다. 원문이 문자함에서 삭제되었다면 상세에 이를 알린다.
- 서버에는 사용자가 승인한 기존 거래 필드와 중복 방지에 필요한 식별 정보만 전송한다. 원문·발신 전화번호를 분석 로그나 오류 수집으로 보내지 않는다.

Google Play에 배포하는 경우 SMS 기반 예산 관리 예외의 적용과 권한 신고를 별도로 확인한다. 예외 목록에 포함된다는 사실이 심사 승인을 보장하지 않는다. [Google Play SMS 권한 정책](https://support.google.com/googleplay/android-developer/answer/10208820?hl=en)

| AC-11 | 7일 이상 미실행, 후보 100건 초과, SMS 1,000건 | 기간·건수 때문에 조용히 누락하지 않고 페이지 처리가 완료된다. |
| AC-12 | 페이지 저장 직전·직후 앱 종료 | 재시도 시 누락·중복 없이 이어진다. |
| AC-13 | 조회 완료 후 지연 저장된 SMS | 중첩 조회 또는 수동 전체 재확인으로 찾는다. |

| AC-17 | 승인과 전액취소 동시 발견 / 부분취소 / 연결 대상 다수 | 연결 관계를 보여주고 명시적 확인 없이 거래를 삭제하지 않는다. |
| AC-18 | 후보 일부 등록 실패·오프라인·연속 탭 | 성공 항목만 처리하며 실패 후보가 남고 재시도해도 중복되지 않는다. |
| AC-19 | 기능 OFF 동안 SMS 수신 후 다시 ON | OFF 기간 SMS는 자동 가져오지 않는다. |
| AC-20 | 잠금·로그아웃·계정 전환 중 조회 완료 | 다른 계정이나 잠금 화면에 후보·원문을 표시하지 않는다. |
| AC-21 | RCS·MMS/LMS·카드 앱 푸시만 도착 | SMS를 가져온 것으로 표시하지 않으며 지원 범위를 안내한다. |
| AC-22 | 원문 삭제 후 후보 열기, 앱 오류 로그·네트워크 검사 | 원문 부재를 처리하고 원문·발신번호가 외부로 전송되지 않는다. |

## 10. 성공 지표와 완료 판단

- 지원 SMS 테스트 세트에서 기준 이후 승인·취소 후보 발견률 100%, 승인 전 거래 생성 0건, 중복 등록 0건.
- 재실행·업데이트·제외·부분 실패 테스트에서 후보 누락과 반복 질문 0건.
- 최초 조회 대상 200건 이하일 때 잠금 해제 후 후보 표시까지 3초 이내를 목표로 한다. 1,000건 테스트에서도 홈 화면을 먼저 표시하고 처리 상태를 제공한다. 목표치는 실제 지원 기기에서 측정한다.
- 사용자가 설정 화면만으로 기능 상태·조회 범위·마지막 결과·다음 조치를 알 수 있다.
- 실제 미인식 기기 또는 동일 조건 기기에서 `앱 종료 → 결제 SMS 수신 → 앱 실행 → 후보 확인 → 승인 → 거래 1건 등록`을 검증해야 완료로 판단한다. 파서 단위 테스트만 통과한 상태를 기능 완료로 보지 않는다.
- 측정은 원문 없는 기기 내 진단을 기본으로 한다. 운영 지표를 위해 문자 내용을 자동 수집하지 않는다.

문서 작성 단계에서는 소스 확인과 공식 Android 자료 검토만 수행했다. 실제 문자 수신 재현, APK 변경 및 위 수용 기준의 실행 결과는 아직 없다.
