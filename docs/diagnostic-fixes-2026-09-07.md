# 진단 점검 후 수정 결과

2026-09-07. [원래 점검 보고서](diagnostic-audit-2026-08-09.md)의 오류와 개선 사항을 반영했다.

## 완료한 수정

| 항목 | 변경 후 동작 |
|---|---|
| B1 미래 예측 일관성 | 선택 월과 무관하게 전체 원본 정보를 참조한다. 원본을 삭제해도 이미 불러온 월별 일정은 새로 불러오기/제외 전까지 유지하며, 계좌·카드 모두 같은 정책을 사용한다. 원본을 찾을 수 없는 미처리 일정은 새 비용으로 계산하지 않는다. |
| B2 월별 금액 반영 | 실제 완료 거래 → 저장된 월별 일정 → 미생성 일정의 원본 금액 순서로 계산한다. 건너뜀은 다시 추가하지 않고, 주간 일정은 빠진 날짜만 예상한다. 대체된 카드대금 기록도 예측 입력에서 제외한다. |
| B3 기간 상태 | 시작 전·진행 중·마감을 구분한다. 지난 소비 월은 남은 0일이며 미래 소진 안내를 표시하지 않는다. 시작 전 기간은 총 일수보다 하루 더 길어지지 않는다. 날짜가 바뀌거나 앱으로 돌아오면 날짜 기준 계산을 갱신한다. 위젯 날짜도 생활비 소비 기간과 맞췄다. |
| B4 999% 표시 | 가용 재원 0원은 비율 없음으로 처리한다. 사용자 설정 한도 사용률과 가용 재원 부족을 따로 안내한다. 경고 상태는 재원 부족을 계속 반영한다. AI 분석에도 이 상태와 마감 여부를 전달한다. |
| B5 거래내역 합계 | 소비 지출, 카드 납부, 이체, 대체 기록을 분리해서 합산·표시한다. 기록을 삭제하지 않고 소비 합계에서 제외되는 이유를 각 행에 표시한다. |
| 소비 기간 연결 | 거래내역 기본 필터를 소비 월로 맞추고 급여 회계 기간을 따로 선택할 수 있게 했다. 홈의 생활비에서 해당 소비 목록으로 이동한다. 과거에 구매한 할부도 선택 소비 월의 회차로 집계하며 편집은 원금을 유지한다. |
| 계산 근거 | 홈에서 수입·고정 지출·카드대금·한도 설정 화면으로 연결되는 상세 설명을 추가했다. 월별 설정 한도와 실제 적용 한도를 함께 표시한다. |
| 정기 계획 영향 안내 | 원본 수정·삭제 전에 유지되는 미처리 일정 건수·월·금액을 표시한다. 새로 불러오기 전 월별 직접 수정액 재산정과 삭제 원본 제외, 완료·건너뜀 보존을 안내한다. 삭제 원본에서 유지된 일정은 표시 배지로 구분한다. |
| 카드 청구액 확인 | 확정 청구액·기록 기반 추정·사용 기록 없음을 구분한다. 추정액과 대체된 정기 원본 금액을 함께 보여주고 청구액/이용기간 설정으로 연결한다. 6주기 차트는 계획·예상 지출로 표시한다. |
| 잔액 확인 | 확인한 0원과 미입력 0원을 구분하는 상태를 추가했다. 잔액 기준일과 오래된 잔액을 안내한다. 미확인 잔액이 섞인 합산 잔고를 확정 잔고처럼 예측하지 않는다. |
| 중복 후보 | 동일 조건의 거래 후보와 계좌 후보를 표시해 기존 수정·삭제 화면에서 확인할 수 있게 했다. 후보라는 이유만으로 거래를 제외하거나 삭제하지 않는다. |
| 진단 내보내기 | 플랫폼·설치 버전·웹 빌드 시각·계산 시각·회계/소비 기간·미반영 동기화 건수·계산 포함 사유를 기록한다. 카드 메모도 제외한다. Android는 기존 임시 파일 및 저장 크기 확인에 JSON 형식 검증과 저장 후 SHA-256 내용 일치 검증을 추가했다. |

## 실데이터 검증

두 파일의 원본 거래를 수정하지 않고 새 계산 코드에 전달했다.

- 8월 계좌 고정 지출: 요약·6주기 예측 모두 4,321,116원.
- 9월 계좌 고정 지출: 요약·6주기 예측 모두 4,267,996원.
- 8월 소비 합계: 거래내역과 요약 모두 2,069,480원. 급여 회계 기간 전체 소비 지출은 7,602,646원이며, 카드 납부 3,720,000원과 대체된 기록 3,834,018원은 별도 분류.
- 9월 소비 합계: 거래내역과 요약 모두 447,660원. 설정 한도 사용률 24.9%, 가용 재원 기준 비율은 없음.
- 모든 겹치는 미래 월의 전체 예측 객체가 두 파일에서 일치.
- 11월 카드 예상액은 양쪽 모두 904,800원. 기존에 불러온 삭제 원본의 7,890원 일정을 유지하는 정책을 명확히 적용했기 때문이다. 원래 보고서의 896,910원은 그 일정을 제외한 실험값이었다. 이제 어느 정책이든 화면 선택만으로 금액이 바뀌지 않는다. 사용하지 않을 일정은 정기납부의 제외 또는 해당 월 새로 불러오기로 정리할 수 있다.
- 8월 소비 기간은 마감, 남은 날짜 0, 소진 예정일 없음. 9월 급여 회계 기간은 시작 전 총 30일.

재현: [수정 검증 스크립트](../scripts/verify-diagnostic-fixes.ts). 검증 결과 JSON은 로컬 `artifacts` 폴더에 생성된다.

- 대시보드·거래내역 렌더링 테스트 3개 통과. 합계 290개.

- 실제 Android 기기의 파일 선택·저장 왕복은 미검증이다. 저장 경로별 동작은 기기에서 추가 확인이 필요하다.

## 운영 데이터와 배포

실제 계좌·거래·월별 계획·카드 청구금액은 변경하지 않았다. 중복 후보가 실제 중복인지, 9월 우리카드 청구액이 실제로 0원인지는 진단 파일만으로 알 수 없어 확인 기능으로 연결했다. 실제 청구액을 추측해서 입력하지 않는다.

코드와 로컬 빌드를 완료한 상태이며, 운영 서버 배포·사용자 기기에 설치한 앱 업데이트는 수행하지 않았다. Android debug APK는 검증용이며 기존 배포 APK의 서명과 다를 수 있다.

Android debug APK 생성까지 통과했다. 검증용 APK는 로컬 `artifacts/expendbreak-diagnostic-fixes-debug.apk`에 생성했다.
