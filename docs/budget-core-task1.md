# Task 1: 계산 코어 검증

`src/types/budget.ts`와 `src/lib/calculator.ts`는 기존 저장 모델과 독립된 순수 계산 모듈이다. 운영 데이터에 쓰거나 기존 화면의 계산을 교체하지 않는다.

## 로컬 화면

`npx vite --host 127.0.0.1 --port 5188` 실행 후 `http://127.0.0.1:5188/budget-core-demo.html`을 연다. 목업 전용 HTML 진입점으로, 기본 운영 빌드에는 포함되지 않는다. Firebase, 로그인, API, 저장소를 사용하지 않는다.

기본 사례는 변동 한도 600,000원, 어제까지 지출 100,000원, 미결제 예정 변동비 20,000원, 오늘 포함 13일이다. 오늘 배정액은 36,923원으로 고정된다. 오늘 지출 50,000원을 적용하면 오늘 남은 금액은 -13,077원, 현재 안전 잔액은 430,000원, 내일 예상 배정액은 35,833원이다.

## 입력 계약과 경계 처리

- 날짜는 유효한 `YYYY-MM-DD` 현지 달력 날짜다. 일수 차이는 UTC 달력 연산으로 구해 시간대와 일광절약시간의 영향을 없앤다. 계산 내부에서 현재 시각을 읽지 않는다.
- `budgetPeriodKey`는 주기 **시작 월**이다. 시작일 25일이면 2026-10 주기는 10월 25일~11월 24일이다. 실제 날짜에서 매번 재계산하지 않고 거래·회차에 명시한 키로 집계한다. 조기 급여는 `getBudgetPeriodKey(원래급여예정일, monthStartDay)`로 키를 부여한다.
- 입력 금액은 각각 `Math.floor` 처리하며, 음수·무한대·안전한 정수 범위 초과는 거부한다. 환불·계좌 이체·카드 결제 대금은 향후 기존 모델과 연결할 때 별도 정규화가 필요하다.
- 실제 지출은 오늘까지 발생한 현재 주기 거래만 집계한다. 미결제 예정 회차는 기한 경과분도 예약하며 `posted`, `skipped`는 제외한다. 반영 완료된 회차는 거래에서 한 번만 합산한다.
- 고정비 예산은 활성 고정지출 템플릿 합계이며 변동 한도와 독립적이다. 일회성 변동지출도 오늘·현재 안전 잔액에서는 차감한다.
- 지출 속도는 오늘 포함 최근 최대 14일의 일상 변동지출을 사용한다. 이전 주기의 최근 거래도 속도 산출에는 포함한다. `observationStartDate`는 0원 지출일도 포함해 거래 기록이 완전한 첫날이며, 첫 거래일과 다르다. 관측 3일 미만은 `null`과 `insufficient_data`로 반환해 화면에서 ‘데이터 부족’을 표시한다.
- 일평균 표시액은 정수로 내린다. 미래 지출은 원래 합계 × 남은 일수 ÷ 관측 일수의 정수 나눗셈으로 계산해 중간 반올림 오차를 피한다.
- 고정비의 일회성 표시는 확정 고정지출에 이미 포함되므로 특별지출 항에 다시 더하지 않는다. 마지막 날의 내일 배정액은 `null`이다. 오늘 초과액과 안전 잔액은 음수를 허용하고, 배정액은 0원 아래로 내리지 않는다.

검증: `npm run lint`, `npm test`. 계산 코어의 경계 사례는 `src/lib/calculator.test.ts`에서 검증한다.
