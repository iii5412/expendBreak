# Task 4: 자연어 입력과 소비 피드백

## 사용 흐름

실제 계정은 기존 `/?view=budget`에서 PIN 로그인 후 사용한다. `+ 추가 → 한 문장으로 기록하기`에 직접 쓴 문장을 입력한다. 개인 가맹점 규칙, 기본 사전, Gemini 순서로 처리한다. `배민 저녁 24,900원`은 기본 사전만으로 처리되어 AI 요청 횟수를 쓰지 않는다. AI가 꺼져 있으면 모르는 사용처는 수동 입력으로 안내한다.

추천 결과는 저장하지 않는다. 신뢰도 0.80 이상은 카테고리를 미리 선택해 확인하고, 0.55 이상 0.80 미만은 직접 선택해야 한다. 0.55 미만은 거래 설명 보충과 카테고리 선택을 요구한다. ‘추천 내용 확인 후 적용’으로 금액·유형·날짜·가맹점을 채운 뒤 저장 버튼을 별도로 눌러야 한다. 수입은 변동지출 한도를 자동으로 늘리지 않는다. AI 결과를 수정해도 `aiReviewed`를 기록하고, 사용자가 요청한 경우에만 수정한 가맹점 규칙을 보관한다. 규칙 저장에 실패해도 이미 저장한 거래를 재저장하지 않는다.

관리의 AI 자연어 분류·소비 분석 스위치는 기존 계정 프로필에 저장한다. 켤 때 전송 범위를 설명하고 기존 aiConsentAt에 동의를 기록한다. 분석 탭은 사용자 요청 시에만 피드백을 생성한다.

## API와 검증

기존 `/api/ai/classify`, `/api/ai/feedback` 경로를 유지하며 새 화면은 `contract: budget-v1`을 사용한다. 로그인은 기존 세션 미들웨어로 보호한다. 알 수 없는 계약 버전은 거부한다. 이전 화면의 요청·응답 형식은 유지한다.

분류 응답은 금액 1원 이상 정수, 실제 달력 날짜, 수입/지출 유형, 유효한 동일 유형 카테고리, 신뢰도 0~1, 가맹점·메모·이유와 확인 여부를 검증한다. 잘못된 금액을 반올림하거나 없는 카테고리를 임의로 바꾸지 않고 수동 입력으로 전환한다. 서버·클라이언트 모두 검증하며 needsConfirmation은 항상 true다. 키와 모델 설정은 서버에만 있고 새 화면 모델은 `GEMINI_MODEL || gemini-3.5-flash-lite`다.

피드백에는 계산 코어의 예산·지출·카테고리별 금액/횟수만 담는다. 거래·가맹점·메모·계좌 객체는 허용하지 않는다. 한 줄 진단, 잘한 점 1개, 위험 요인 최대 2개, 주간 행동 최대 3개를 검증한다. 각 절감액은 정수 원의 최소/최대 범위이며 행동별 상한의 합계가 집계에서 뒷받침할 수 있는 범위를 벗어나면 거부한다. 과거 API도 모델에 전달하는 집계 필드를 허용 목록으로 제한한다.

문자 가져오기 데이터는 새 입력 흐름에 연결하지 않았다. 직접 입력에서도 문자 알림 표식, 계좌·발신번호 표식, 전화번호·계좌번호로 보이는 숫자 패턴을 클라이언트와 서버에서 차단한다. 기존 분류 API에도 같은 텍스트 차단을 적용했다. 문장과 API 키를 로그에 쓰지 않는다.

## 시간·비용 제어

- 브라우저는 요청·JSON 처리·검증을 합쳐 최대 5초를 기다린다. 실패 시 기존 수동 입력 칸으로 이동한다. 창을 닫거나 입력을 바꾸면 요청을 취소하고 늦은 응답을 적용하지 않는다.
- 서버는 한도 조회와 모델 작업을 4.5초로 제한하고 SDK에도 취소 신호를 전달한다.
- 새 화면과 기존 분류·피드백 API는 같은 계정별 일일 30회 한도를 공유한다. 날짜는 한국 시간이다. Firestore Admin 트랜잭션으로 `users/{uid}/aiUsage/{YYYY-MM-DD}`의 횟수만 증가시키며 원문은 저장하지 않는다. 한도 저장소 장애는 AI를 호출하지 않는 방향으로 처리한다. 시도 실패도 한도에 포함될 수 있다.
- 계정·요청 종류·정규화 맥락의 해시로 인스턴스별 메모리 캐시를 구분한다. 유효기간 15분, 최대 500건이며 동시 동일 요청은 합친다. 규칙·캐시 적중은 한도를 소비하지 않는다. 여러 Cloud Run 인스턴스 사이에서 캐시 자체는 공유하지 않지만 일일 한도는 공유한다.

## 로컬 검증과 제한

`budget-app.html?mode=local`은 개인 규칙·기본 사전·수정·저장·설정 보존을 외부 호출 없이 체험하는 모드다. 실제 Gemini 결과를 가장하지 않으며, 모르는 사용처와 AI 소비 분석은 실계정 연결이 필요하다고 안내한다.

현재 로컬 환경에는 GEMINI_API_KEY와 실제 계정 로그인/한도 저장소용 Google 서버 자격 증명이 없어 실제 Gemini 연동은 검증하지 않았다. 키의 설정 여부만 확인했으며 값은 출력하지 않았다. 모델·한도 저장소를 대체한 HTTP 테스트로 스키마 거부, 계정별 캐시, 공유 한도, 장애·시간 초과를 검증했다. 운영 데이터와 보안 규칙은 변경하지 않았고 배포·push도 하지 않았다. 서버 소스를 수정한 뒤에는 개발 서버를 재시작해야 새 API 코드가 반영된다.

검증: `npm run lint`, `npm test`, `npm run build`, 변경 AI 모듈 ESLint. 브라우저에서 예문 해석·확인 후 저장, 카테고리 수정·규칙 재사용, 민감 입력 거부를 확인한다. 차트·배포 구성은 Task 5 범위로 남긴다.
