# ExpendBreak 사용자 편의 개선 PRD

작성일: 2026-08-11
대상 버전: 현재 `main` (d255528) 기준
선행 문서: `PRD-production-hardening.md`, `PRD-life-ledger-expansion.md`, `IMPLEMENTATION-STATUS.md`

## 1. 배경

`PRD-production-hardening.md`는 데이터 무결성·보안·정확성을 목표로 했고 대부분 반영됐다. 그 결과 계산 정확도와 데이터 안전성은 확보됐지만, **매일 반복되는 조작의 편의성**은 아직 초기 프로토타입 수준에 머물러 있다.

이 문서는 기능 추가가 아니라 **기존 기능을 쓰는 과정의 마찰**을 제거하는 것을 범위로 한다. 코드 전수 점검으로 확인한 실제 지점만 다루며, 추정에 근거한 항목은 넣지 않았다.

## 2. 목표와 비목표

### 목표

- 실수로 데이터를 잃을 가능성을 구조적으로 제거한다.
- 저장이 실제로 서버에 반영됐는지 사용자가 항상 알 수 있게 한다.
- 하루 여러 번 반복되는 조작(기록·확인·월 이동)의 단계와 인지 부하를 줄인다.
- 월급 생활자의 실제 회계 주기(급여일 기준)와 앱의 기간 개념을 일치시킨다.
- 모바일 단독 사용에 필요한 최소 조건(터치 타깃, 안전 영역, 홈 화면 설치)을 충족한다.

### 비목표

- 다중 사용자·공유 가계부
- 새로운 AI 기능 추가 (기존 AI 흐름의 UI 개선은 범위에 포함)
- 디자인 시스템 전면 리뉴얼 (색·타이포의 국소 조정만 포함)
- 은행/카드사 자동 연동

## 3. 현황 진단

### 3.1 파괴적 동작에 안전장치가 없다

| 지점 | 현상 |
|---|---|
| [HistoryView.tsx:337](src/components/HistoryView.tsx:337) | 거래 삭제 버튼이 확인 절차 없이 `onDeleteTransaction(t.id)`를 즉시 실행한다. 되돌릴 수단이 전혀 없다. |
| 전체 28개 지점 | `alert` / `confirm` / `window.prompt` 네이티브 다이얼로그에 의존한다. |

거래 삭제는 이 앱에서 가장 되돌리기 어려운 동작인데, 아이콘 버튼 한 번으로 실행된다. 목록이 조밀해(`p-1` 아이콘 버튼, 3.5px 간격) 수정 버튼과 오조작 거리도 가깝다.

네이티브 다이얼로그 28개소는 다음 문제를 만든다.
- 모바일에서 시스템 다이얼로그가 앱 컨텍스트를 끊고, 브라우저에 따라 "이 사이트가 추가 대화상자를 표시하지 못하게 함" 체크박스가 노출돼 이후 확인 절차가 아예 사라진다.
- 유효성 오류를 `alert`로 던지므로([AddTransactionModal.tsx:183](src/components/AddTransactionModal.tsx:183), [:247](src/components/AddTransactionModal.tsx:247), [:322](src/components/AddTransactionModal.tsx:322) 등) 어느 필드가 문제인지 화면에 남지 않는다. 확인을 누르는 순간 오류 정보가 사라진다.
- `AccountsView`에는 이미 토스트([AccountsView.tsx:460](src/components/AccountsView.tsx:460))와 5초 실행 취소([AccountsView.tsx:466](src/components/AccountsView.tsx:466))가 구현돼 있으나 그 화면 안에만 갇혀 있다. 같은 앱에서 화면마다 피드백 방식이 다르다.

### 3.2 저장이 됐는지 사용자가 알 수 없다

[storage.ts:341](src/utils/storage.ts:341) `saveTransaction`은 localStorage에 먼저 쓰고 `syncTransactionToFirestore(newTx)`를 **await 없이** 호출한다. 동기화가 실패해도 UI는 성공과 완전히 동일하게 동작하고 모달이 닫힌다.

실패는 다음 로그인 시 outbox flush([storage.ts:108](src/utils/storage.ts:108))에서야 드러나며, 그때 나오는 메시지는 "이전에 저장하지 못한 변경사항을 DB에 반영하지 못했습니다"이다. 사용자는 **어떤 거래가** 미반영인지 알 수 없다.

예외적으로 월 용돈 한도만 저장 실패를 사용자에게 알린다([storage.ts:536](src/utils/storage.ts:536), [ManagementView.tsx:308](src/components/ManagementView.tsx:308)). 나머지 저장은 조용히 실패한다.

네트워크 상태 감지(`navigator.onLine`), 재시도 큐 UI, 동기화 상태 표시는 전무하다.

### 3.3 기간(월) 개념이 화면마다 어긋난다

- 전역 상태 `currentYM`([App.tsx:73](src/App.tsx:73))은 홈 요약·카테고리 분석·카드 정산·정기 발생 건 전부의 기준이다.
- 그런데 이 값을 바꾸는 UI는 **정기납부 탭에만** 있다([RecurringPaymentView.tsx:75-83](src/components/RecurringPaymentView.tsx:75)).
- 결과: 홈에서 지난달을 볼 방법이 없다. 반대로 정기납부 탭에서 월을 옮긴 뒤 홈으로 돌아오면 홈 수치가 조용히 과거 월로 바뀌어 있다. 홈 상단에는 `{summary.yearMonth} 기준` 배지만 있을 뿐 되돌릴 컨트롤이 없다([DashboardView.tsx:113](src/components/DashboardView.tsx:113)).
- 내역 탭은 아예 다른 축(오늘/최근 7일/최근 30일/전체)을 쓴다([HistoryView.tsx:138-143](src/components/HistoryView.tsx:138)). "이번 달 용돈 45만 원 썼다"를 홈에서 보고 내역에서 그 45만 원의 근거를 찾으려면 기간이 맞지 않는다.
- 계좌 탭은 또 다른 로컬 월 상태 `cardPaymentMonth`를 따로 둔다([AccountsView.tsx:83](src/components/AccountsView.tsx:83)).

한 앱에 월 기준이 네 종류로 존재한다.

### 3.4 월급일 기준 예산 주기를 지원하지 않는다

`UserProfile.monthStartDay`가 타입([types.ts:173](src/types.ts:173))과 초기값([initialData.ts:43](src/data/initialData.ts:43))에만 존재하고, **계산에서 한 번도 참조되지 않는다.** `getMonthDaysInfo`([calculations.ts:71](src/utils/calculations.ts:71))는 달력 월 1일~말일로 고정이다.

25일 급여 사용자는 매월 25일에 돈이 들어오는데 앱은 1일에 예산을 리셋한다. "오늘 안전 용돈"([DashboardView.tsx:136](src/components/DashboardView.tsx:136))은 이 앱의 핵심 지표인데, 급여 주기와 어긋난 남은 일수로 나눈 값이 된다. 설정 화면에도 이 항목을 바꿀 UI가 없다.

### 3.5 하단 내비게이션이 모바일 터치 기준에 미달한다

[BottomNav.tsx](src/components/BottomNav.tsx)는 한 줄에 탭 6개 + 중앙 FAB, 총 7개 타깃을 배치한다. 각 탭은 `py-1 px-1.5`에 `text-[11px]`, 아이콘 `w-4 h-4`이다. 360px 폭 기준 탭 하나당 유효 폭이 약 40px 미만이고 높이는 약 34px로, 권장 최소 44×44px에 미달한다. "정기납부"·"계좌/카드"는 11px 4~5글자라 가독성도 떨어진다.

또한 `env(safe-area-inset-bottom)`을 적용하지 않아 iOS 홈 인디케이터 영역과 겹친다. `index.html`의 viewport에도 `viewport-fit=cover`가 없다.

### 3.6 접근성이 사실상 미구현이다

- 전체 컴포넌트의 `aria-*` / `role` 속성 합계 **6개**.
- 모달 4종(`AddTransactionModal`, `AppLockModal`, `HistoryView` 수정 모달, `ReceiptDetailsModal`)에 `role="dialog"`, `aria-modal`, 포커스 트랩, ESC 닫기, 배경 스크롤 잠금이 모두 없다. 키보드 사용자는 모달 뒤 요소로 탭이 빠져나간다.
- 오류 메시지에 `role="alert"` / `aria-live`가 없어 스크린리더에 전달되지 않는다.
- `text-[10px]` 사용이 다수이고, `text-slate-500`(#64748B)을 `bg-slate-950`(#020617) 위에 쓰는 조합이 반복돼 WCAG AA 대비에 미달한다. 카드 요약의 보조 설명이 대부분 이 조합이다.

### 3.7 첫 사용과 반복 사용의 요구가 충돌한다

- 홈 최하단 "월급 생활자 추천 초기 설정" 카드([DashboardView.tsx:457](src/components/DashboardView.tsx:457))가 **조건 없이 항상 노출**된다. 이미 정기 항목을 등록한 사용자에게는 영구 잡음이며, 실수로 누르면 350만/120만/38만 정기 항목 3건이 생성된다.
- 프리셋 금액이 코드에 하드코딩돼 있어([App.tsx:215-263](src/App.tsx:215)) 실제 급여와 맞추려면 생성 후 3건을 각각 수정해야 한다.
- 반대로 진짜 첫 실행 안내(용돈 한도 설정 → 정기 항목 → 계좌 등록)는 없다. 신규 사용자는 빈 대시보드에서 시작한다.

### 3.8 금액 입력이 한국 원화 사용에 맞지 않는다

거래 금액 입력이 `type="number"` 그대로다([AddTransactionModal.tsx:586](src/components/AddTransactionModal.tsx:586), [:842](src/components/AddTransactionModal.tsx:842), [:952](src/components/AddTransactionModal.tsx:952)). 원화는 자릿수가 커서(1,250,000) 천 단위 구분 없이는 입력값을 눈으로 검산하기 어렵다. 일부 입력만 `inputMode="numeric"`을 지정해 모바일 키패드도 일관되지 않다.

### 3.9 잠금 화면이 기본 PIN을 그대로 안내한다

[AppLockModal.tsx:63](src/components/AppLockModal.tsx:63)과 [:76](src/components/AppLockModal.tsx:76)이 "(기본 설정 PIN: 0000)"을 화면과 placeholder에 노출한다. 개발 편의용 문구가 운영 화면에 남아 있는 상태다. 또한 유휴 잠금 30분이 하드코딩([App.tsx:151](src/App.tsx:151))이라 조절할 수 없고, 잠금 직전 경고도 없어 입력 중 갑자기 잠기면 작성 내용이 사라진다.

### 3.10 PWA 미구성

`manifest.json`, 서비스 워커, 앱 아이콘이 없다. 매일 여러 번 쓰는 개인 가계부인데 홈 화면 설치와 오프라인 조회가 불가능하다. 지하철·매장처럼 네트워크가 불안정한 곳에서 지출을 기록하는 상황이 주 사용 시나리오임에도 그렇다.

## 4. 개선 요구사항

우선순위: **P0** 데이터 손실·신뢰 문제 / **P1** 일상 조작 마찰 / **P2** 완성도

### P0-1. 거래 삭제 보호

- 내역 목록의 삭제는 **인앱 확인 시트**를 거친다. 시트에는 사용처·금액·날짜·카테고리를 표시해 무엇을 지우는지 확인 가능해야 한다.
- 삭제 실행 후 **10초 실행 취소 스낵바**를 노출한다. 실행 취소 시 동일 ID로 거래가 복원되고, 연결된 정기 발생 건 상태도 함께 되돌아간다.
- 실행 취소 창이 끝나기 전 화면을 이동해도 스낵바는 유지된다.

**수용 기준**: 삭제 → 실행 취소 → 새로고침 시 거래가 원래대로 존재하고 월 요약 수치가 삭제 전과 일치한다.

### P0-2. 전역 피드백 체계 도입

- 앱 전역 `ToastProvider`와 `ConfirmDialog`를 신설하고, 기존 `alert`/`confirm`/`window.prompt` **28개소를 전부 치환**한다.
- 파괴적 확인(삭제, 전체 초기화, 분류 일괄 정정)은 위험 색상과 명시적 동사 버튼("삭제", "정리 실행")을 쓴다. "확인/취소"는 쓰지 않는다.
- 폼 유효성 오류는 토스트가 아니라 **해당 입력 필드 아래 인라인 메시지**로 표시하고, 첫 오류 필드로 포커스를 옮긴다.
- `AccountsView`의 토스트/실행 취소는 새 공통 컴포넌트로 이관하고 중복 구현을 제거한다.

**수용 기준**: 소스 전체에서 `alert(` / `confirm(` / `window.prompt(` 검색 결과 0건. 금액 미입력 저장 시 금액 필드가 강조되고 포커스가 이동한다.

### P0-3. 저장·동기화 상태 가시화

- 전역 동기화 상태(`synced` / `syncing` / `pending` / `offline` / `failed`)를 두고 `Navbar`에 배지로 상시 표시한다.
- 거래 저장 시 Firestore 반영 완료를 기다려 **성공 토스트**를 띄운다. 실패 시 "기기에 저장했고 연결되면 자동 반영합니다"를 명시하고 미반영 건수를 배지에 누적한다.
- 설정에 **미반영 변경 목록** 화면을 추가한다. 항목별 재시도와 전체 재시도를 제공한다.
- `navigator.onLine`과 `online`/`offline` 이벤트를 구독해 오프라인 배너를 표시하고, 온라인 복귀 시 outbox를 자동 flush한다.

**수용 기준**: 네트워크를 끊고 거래 3건을 기록하면 오프라인 배너와 "미반영 3"이 표시된다. 네트워크 복구 후 자동으로 0이 되고 Firestore에 3건이 존재한다.

### P0-4. 기본 PIN 안내 문구 제거

- 잠금 화면의 "(기본 설정 PIN: 0000)" 문구와 placeholder 내 기본값 노출을 제거한다.
- placeholder는 "접근 암호(PIN) 입력"으로 바꾼다.

**수용 기준**: 잠금 화면 어디에도 실제 PIN 값이 나타나지 않는다.

### P1-1. 기간 컨트롤 통합

- 월 선택기를 **상단 공통 영역**으로 올려 홈·정기납부·계좌·분석에서 동일하게 노출·조작한다. `‹ 2026년 8월 ›` 형태와 "이번 달로" 바로가기를 제공한다.
- 내역 탭은 기본을 **현재 회계 월**로 바꾸고, 기존 오늘/7일/30일/전체는 보조 필터로 유지한다.
- `AccountsView`의 독립 월 상태 `cardPaymentMonth`는 전역 기준과 동기화하되, 카드 결제월만 별도로 볼 필요가 있으면 명시적 토글로 분리한다.
- 현재 월이 아닌 과거·미래 월을 볼 때는 화면 상단에 "과거 월 조회 중" 안내를 띄워 홈 수치가 왜 다른지 알 수 있게 한다.

**수용 기준**: 정기납부에서 7월로 이동 후 홈으로 이동하면 홈 상단 선택기에도 7월이 표시되고 "과거 월 조회 중" 안내가 보인다. "이번 달로" 한 번으로 전 화면이 8월로 복귀한다.

### P1-2. 급여일 기준 회계 주기 적용

- 설정에 **월 시작일**(1~28일, 기본 1일) 설정 UI를 추가한다.
- `getMonthDaysInfo` / `calculateMonthSummary` / 카테고리 분석 / 카드 정산 / CSV 내보내기가 모두 `monthStartDay`를 기준으로 기간을 산출하도록 변경한다.
- 기간 라벨을 실제 범위로 표기한다. 예: `2026-08 (7/25~8/24)`.
- 기존 사용자의 값은 1일이므로 동작 변화가 없어야 한다. 변경 시에는 영향 범위(요약·분석·CSV)를 미리 안내한다.

**수용 기준**: 월 시작일을 25일로 설정하면 홈의 "남은 날짜"와 "오늘 안전 용돈"이 다음 24일까지를 기준으로 계산되고, 회귀 테스트에서 1일 설정 시 기존 결과와 완전히 동일하다.

### P1-3. 하단 내비게이션 재구성

- 하단 탭을 **4개 + 중앙 FAB**로 줄인다: 홈 / 내역 / 분석 / 더보기. 정기납부·계좌/카드·설정은 "더보기"로 이동하거나 각 화면의 진입점을 유지한다.
- 모든 탭 터치 타깃을 최소 44×44px로 확보하고 라벨은 `text-xs` 이상으로 올린다.
- `env(safe-area-inset-bottom)` 패딩을 적용하고 `index.html` viewport에 `viewport-fit=cover`를 추가한다.
- 현재 탭에 `aria-current="page"`를 부여한다.

**수용 기준**: iPhone 세로 화면에서 하단 탭이 홈 인디케이터와 겹치지 않고, 각 탭 히트 영역이 44px 이상이다.

### P1-4. 금액 입력 개선

- 모든 금액 입력에 **천 단위 구분 표시**를 적용한다(표시는 `1,250,000`, 저장은 정수).
- 모든 금액 입력에 `inputMode="numeric"`을 통일 적용한다.
- 입력란 아래에 `+1만 / +5만 / +10만` 빠른 증감 칩과 한글 판독("일백이십오만 원")을 제공한다.
- `type="number"`의 스크롤 휠 값 변경 오작동을 막는다.

**수용 기준**: 모바일에서 금액 필드 포커스 시 숫자 키패드가 뜨고, 입력 중 실시간으로 콤마가 표시되며, 저장값은 콤마 없는 정수다.

### P1-5. 온보딩과 프리셋 분리

- 홈의 프리셋 카드는 **정기 항목이 0건일 때만** 노출한다.
- 프리셋 적용 전에 월 수입·고정비·용돈 한도를 **입력받는 3단계 온보딩 시트**로 대체한다. 하드코딩 금액을 기본값 힌트로만 쓴다.
- 온보딩 완료 여부를 `UserProfile`에 저장하고, 건너뛰기를 허용한다.
- 정기 항목이 0건인데 온보딩을 건너뛴 사용자에게는 홈에 접힌 형태의 안내 줄만 남긴다.

**수용 기준**: 정기 항목이 1건 이상이면 홈에서 프리셋 카드가 보이지 않는다. 온보딩으로 생성한 정기 항목의 금액이 사용자가 입력한 값과 일치한다.

### P1-6. 잠금 정책 사용자 설정화

- 유휴 잠금 시간을 설정 가능하게 한다(5분 / 15분 / 30분 / 1시간 / 사용 안 함, 기본 30분).
- 잠금 60초 전 경고 토스트를 띄우고 "계속 사용" 버튼으로 연장할 수 있게 한다.
- 거래 입력 모달에 미저장 내용이 있으면 잠금 시 임시 보관하고, 잠금 해제 후 "작성 중이던 내용을 복구할까요?"를 제안한다.

**수용 기준**: 30분 유휴 후 잠금 직전 경고가 표시되고, 입력 중이던 금액·사용처가 잠금 해제 후 복구된다.

### P2-1. 접근성 기준선 확보

- 공통 `Modal` 컴포넌트를 만들어 4개 모달에 적용한다: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, 포커스 트랩, ESC 닫기, 배경 스크롤 잠금, 닫은 뒤 트리거로 포커스 복귀.
- 아이콘 전용 버튼 전부에 `aria-label`을 부여한다(내역의 수정/삭제, 검색 지우기, 모달 닫기 등).
- 오류·상태 메시지에 `role="alert"` 또는 `aria-live="polite"`를 적용한다.
- 본문 최소 글자 크기를 12px로 올리고, 보조 텍스트 색을 `text-slate-400` 이상으로 조정해 대비 4.5:1을 충족한다.
- 진행률 바에 `role="progressbar"`와 값 속성을 부여한다.

**수용 기준**: 키보드만으로 거래 추가 → 저장 → 모달 닫기까지 수행 가능하고, 자동 접근성 검사에서 대비 위반 0건이다.

### P2-2. PWA 구성

- `manifest.webmanifest`(이름·아이콘 192/512·`display: standalone`·`theme_color: #020617`)와 앱 아이콘을 추가한다.
- 앱 셸과 정적 자산을 캐싱하는 서비스 워커를 도입해 오프라인에서 조회·기록이 가능하게 한다(기록은 P0-3 outbox로 연결).
- 홈 화면 추가 안내를 설정 화면에 1회 노출한다.

**수용 기준**: 모바일 브라우저에서 설치 배너가 뜨고, 설치 후 비행기 모드에서 앱이 열려 최근 데이터 조회와 거래 기록이 가능하다.

### P2-3. 홈 정보 밀도 정리

- 카드 요약 블록의 장문 각주([DashboardView.tsx:324](src/components/DashboardView.tsx:324) 3줄 설명)를 접힘형 "계산 방식" 도움말로 옮긴다.
- 홈 카드 순서를 사용 빈도 기준으로 재배열하고, 카드 표시 여부를 설정에서 켜고 끌 수 있게 한다.
- 빈 상태 문구에 다음 행동 버튼을 붙인다(예: "이번 달 정기 일정 없음" → "정기 항목 추가").

**수용 기준**: 홈 첫 화면(스크롤 없이)에 안전 용돈·사용률·남은 용돈이 모두 보인다.

### P2-4. 내역 조작 효율화

- 목록에서 **스와이프 동작**(왼쪽 수정, 오른쪽 삭제)을 지원하되, 삭제는 P0-1 확인 절차를 그대로 거친다.
- 다건 선택 후 카테고리 일괄 변경을 지원한다.
- 검색어 하이라이트와 최근 검색어를 제공한다.
- 목록 상단에 현재 필터 조건의 합계(수입/지출/순액)를 표시한다.

**수용 기준**: 20건 선택 후 카테고리 일괄 변경이 1회 확인으로 완료되고, 변경 후 실행 취소가 가능하다.
