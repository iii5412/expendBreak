# 중복 계좌 일괄 변경·삭제

## 사용 흐름

계좌·카드의 계좌 삭제 버튼 → 남길 계좌 선택 → 연결 일괄 변경 후 중복 계좌 삭제.

- 삭제할 계좌 자신은 선택 목록에서 제외한다. 대상 계좌는 사용자가 직접 선택한다.
- 카드, 정기 원본, 월별 정기 일정, 거래, 퀵등록의 계좌 연결을 변경한다.
- 과거 거래와 완료·건너뜀 일정, 삭제·비활성 정기 원본도 포함한다.
- 거래 금액·날짜·분류·메모·영수증과 카드 청구액을 보존한다.
- 남길 계좌의 잔액과 잔액 기준일을 유지하며, 중복 계좌 잔액을 더하지 않는다.
- 기존 연결 내역은 접어서 확인할 수 있다.

## 저장 방식

로그인한 사용자 범위의 `/api/bank-accounts/merge`를 추가했다. 앱의 미저장 변경사항을 먼저 동기화한 다음 서버에서 전체 기간을 조회한다. Firestore 트랜잭션 하나에서 연결 필드와 수정 시각을 갱신하고 원본 계좌를 삭제한다. 커밋 실패 시 변경 및 삭제가 모두 반영되지 않는다.

서버 처리 영수증을 `users/{uid}/accountMerges/{sourceId}`에 함께 저장한다. 응답 유실 후 동일 요청을 다시 보내면 최초 결과를 반환하며, 다른 대상 계좌로의 재요청은 거부한다. 남길 계좌가 없거나 자기 자신을 지정한 요청도 거부한다.

Firestore 트랜잭션 제한을 넘는 연결 내역은 일부 변경을 시작하지 않고 중단한다. 현재 진단 데이터는 이 제한보다 작다.

성공한 뒤 현재 기기의 캐시도 갱신한다. 실제 운영 데이터는 개발·테스트 과정에서 변경하지 않았다.

## 검증과 배포

- 전체 테스트 309개 통과. 서버 테스트는 메모리 트랜잭션 어댑터로 전체 기간, 600건 이상의 합성 내역, 커밋 실패, 재시도, 다른 사용자 격리, 금액 보존을 검증했다.
- TypeScript 검사, 프로덕션 웹 빌드, 서버 번들 생성 통과.
- 실제 운영 Firestore에서 병합을 실행하거나 사용자 기기에 설치하는 검증은 수행하지 않았다.
- 새 서버 API가 필요하므로 서버와 앱을 함께 업데이트해야 한다. APK만 교체하고 서버가 구버전이면 안내 오류를 표시하고 계좌를 삭제하지 않는다.
- Android debug APK 빌드 통과. 확인용 파일: artifacts/expendbreak-account-merge-debug.apk.
