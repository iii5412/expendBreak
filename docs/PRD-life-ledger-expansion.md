# PRD — 영수증 OCR 기반 생활 재무 기록 확장

상태: 1차 MVP 구현 완료 / 후속 범위 정의

## 1. 제품 목표

지출 합계만 보는 가계부에서 벗어나, 한 거래와 관련된 영수증 원본·구매 품목·결제수단·메모·생활 맥락을 한곳에 기록하고 다시 찾을 수 있는 1인용 생활 재무 기록장으로 확장한다.

핵심 원칙은 다음과 같다.

- OCR 결과는 제안일 뿐이며 사용자 확인 전에는 거래를 만들지 않는다.
- 원본 이미지는 Firestore에 넣지 않고 소유자 전용 Firebase Storage에 보관한다.
- PIN 로그인 전에는 OCR 기록과 원본을 조회하거나 업로드할 수 없다.
- 카드·계좌번호 전체는 OCR 원문에 보존하지 않고 마지막 네 자리만 허용한다.
- 기존 거래 문서는 그대로 유효하며 영수증 필드는 선택 사항이다.

## 2. 1차 사용자 흐름

1. 거래 추가에서 `영수증`을 선택한다.
2. 후면 카메라로 촬영하거나 앨범 이미지를 선택한다.
3. 브라우저가 이미지를 최대 2,000px JPEG로 압축한다.
4. 인증된 서버가 Gemini로 사용처, 총액, 날짜, 구매 품목과 결제 정보를 추출한다.
5. 사용자가 금액·날짜·사용처·카테고리·결제수단·태그·품목을 확인하고 수정한다.
6. 원본 보관 여부를 선택하고 지출을 저장한다.
7. 거래 내역에서 영수증, OCR 원문과 품목을 다시 열어본다.

## 3. 이번 구현 범위

- 모바일 카메라 촬영과 사진 선택
- JPG/PNG/WEBP 검증, 10MB 원본 제한, 2,000px/8MB 이하 압축
- 소유자 인증 OCR API와 사용자별 10분당 20회 제한
- 총액, 결제일, 시간, 사용처, 영수증 번호, 사업자번호, 공급가/세금, 결제 표시, 카드 마지막 네 자리 추출
- 최대 50개 구매 품목 추출 및 품목명·금액 수정/추가/삭제
- 기존 사용처 규칙과 지출 카테고리 무결성 적용
- 결제 계좌·카드·현금 연결
- 최대 10개의 생활 태그
- 원본 보관 선택과 소유자 전용 Storage 경로
- 거래 검색에 태그, OCR 원문과 품목명 포함
- 영수증 전용 필터와 상세 보기
- CSV에 태그, 입력 방식, 영수증 번호와 품목명 포함
- 거래 삭제/전체 초기화 시 연결 원본 정리

## 4. 개인정보 및 데이터 정책

- 사진은 OCR 요청 시 Gemini API로 전송된다. AI 기능 동의와 활성화가 선행되어야 한다.
- 서버 OCR 엔드포인트는 이미지를 저장하지 않는다.
- 사용자가 원본 보관을 선택한 경우에만 `users/{uid}/receipts/{receiptId}/original.jpg`에 저장한다.
- 영수증 원문에서 13~19자리 결제 번호 형태를 마스킹한다.
- 원본은 공개 다운로드 URL이 아니라 로그인한 Firebase Storage SDK로 읽는다.
- 거래와 원본 삭제가 분리 실패할 가능성을 운영 로그로 감시하고 고아 파일 정리 작업을 후속 제공한다.

## 5. 후속 제품 로드맵

### P1 — 생활 거래 완성도

- 환불·취소 거래를 원거래와 연결하고 순지출을 자동 계산한다.
- 할부 원금, 회차, 남은 회차와 카드 청구월을 기록한다.
- 공동 지출의 정산 받을 금액과 정산 완료 상태를 관리한다.
- 병원비·교육비·기부금 등 연말정산 증빙 태그와 증빙 누락 목록을 제공한다.
- 보증기간, 교환기한, 구매처 연락처를 영수증에서 추출해 알림을 제공한다.

### P2 — 현금흐름 전체 관리

- 계좌 간 이체는 수입과 지출 두 건이 아닌 내부 이동으로 기록한다.
- 대출 원금·이자, 빌려준 돈·빌린 돈과 상환 일정을 관리한다.
- 예정 수입, 미수금, 환급 예정금과 실제 입금의 차이를 관리한다.
- 현금 잔액 조정과 계좌 수동 snapshot 변경 이력을 남긴다.
- 구독·정기 결제 가격 인상과 중복 구독을 감지한다.

### P3 — 회고와 탐색

- 태그·품목·사용처별 장기 가격 추이와 반복 구매를 보여준다.
- `여행`, `이사`, `육아` 같은 생활 프로젝트별 예산과 실제 비용을 묶는다.
- 월별 숫자뿐 아니라 사진·메모 중심의 재무 일지를 제공한다.
- 영수증 미첨부 고액 거래, OCR 저신뢰 거래와 중복 의심 거래를 검토함으로 모은다.

## 6. 완료 조건

- 원본이 없는 기존 거래가 수정·조회·집계에서 정상 동작한다.
- OCR 결과는 사용자 확인 없이 저장되지 않는다.
- OCR이 잘못 읽어도 모든 핵심 필드와 품목을 수정할 수 있다.
- 다른 UID와 로그인 전 사용자는 영수증 문서와 원본을 읽거나 쓸 수 없다.
- 원본 저장 실패 시 거래 저장을 중단하고 이미 업로드된 파일을 정리한다.
- 거래 검색으로 영수증 품목명과 생활 태그를 찾을 수 있다.
- 영수증 삭제와 전체 초기화가 연결 이미지를 함께 정리한다.
