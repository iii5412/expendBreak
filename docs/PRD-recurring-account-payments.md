# 정기납부 개편 PRD — 급여일 계좌별 이체와 일괄 납부

- 작성일: 2026-09-10
- 상태: 핵심 범위 구현 완료
- 대상: 정기납부 탭, 급여일 설정의 계좌별 이체 단계, 연결된 납부 상태 및 거래 기록
- 핵심 목표: **이번 주기에 총 얼마가 나가고, 어느 계좌에 얼마를 보내야 하며, 그 돈으로 무엇을 내는지 확인하고 계좌 단위로 처리한다.**

## 구현 결과

- 정기납부 기본 화면을 총 지출예정액과 계좌별 보낼 금액 중심으로 교체했다.
- 계좌별 상세에서 직접 고정지출과 카드대금을 함께 확인하고 일괄 납부할 수 있다.
- 이체 준비 금액은 실제 납부 상태와 분리해 주기·계정·계좌별로 저장하며 급여 설정 화면과 공유한다.
- 계좌 처리로 생성된 묶음은 해당 묶음이 바꾼 항목만 취소할 수 있다.
- 추정 0원 카드대금은 확인 대상으로 남기고, 확정 0원은 거래 없이 납부 없음으로 표시한다.
- 전체 항목의 수정·제외·완료 취소와 카드대금 중복 검토는 접힌 관리 영역에 유지했다.

## 1. 사용자 문제와 제품 방향

사용자는 급여일에 고정지출을 위한 돈을 한 번에 배분하려고 정기납부를 연다. 현재는 수입, 계좌 고정지출, 카드 결제 고정항목, 카드대금, 개별 일정과 관리 기능이 연속으로 노출된다. 사용자가 직접 항목을 읽고 출금 계좌별로 다시 합산해야 한다.

카드대금은 연결된 결제계좌에서 빠져나가는 금액이다. 정기납부에서는 그 계좌의 납부 구성 항목으로 보여주고, 카드별 별도 납부 체크를 요구하지 않는다.

화면의 기본 단위를 **개별 지출 항목에서 납부 계좌로 변경**한다. 첫 화면은 총액과 계좌별 할 일에 집중하고, 연결 항목은 계좌를 펼쳤을 때 확인한다.

사용자 핵심 과업:

1. 이번 달 고정지출과 카드대금을 위해 필요한 총액을 확인한다.
2. 각 계좌로 보낼 금액과 계좌번호를 확인한다.
3. 궁금한 계좌만 펼쳐 연결된 고정지출과 카드대금을 확인한다.
4. 계좌에서 한 번 납부처리하면 해당 계좌의 대상 항목이 함께 완료된다.

## 2. 현재 구현에서 확인한 내용

| 현재 구조 | 개편 방향 |
|---|---|
| `RecurringPaymentView.tsx`는 여러 요약과 별도 카드대금 목록, 개별 정기항목 목록을 표시한다. | 총액 요약 → 계좌 목록 → 접힌 보조 기능 순서로 재구성한다. |
| `PaydaySetupSheet.tsx`에는 계좌별 이체 목록과 선택 항목 처리 기능이 있다. | 정기납부와 급여 설정이 동일한 계좌별 계획과 처리 기능을 사용한다. |
| `paydayTransfers.ts`는 계좌 고정지출과 연결 카드대금을 이미 묶는다. | 집계 규칙을 공통화하되, 계좌 역할·완료 상태·이체 가능액을 보완한다. |
| 급여 설정의 계좌 처리 함수는 항목별 납부 함수를 순차 호출한다. | 일부만 저장된 상태를 전체 완료로 표시하지 않는 묶음 저장이 필요하다. |
| `setCardSettlementPaid`는 카드 상태와 `card_settlement` 거래를 만든다. | 카드 상태는 계좌 처리에 연동하되 소비 중복 방지 규칙은 유지한다. |
| 계좌 잔액은 사용자가 입력한 기준일 있는 스냅샷이다. | 표시된 잔액 전체를 자동으로 이체 필요액에서 빼지 않는다. |
| 전역 기간 선택기는 급여일 기준 주기를 사용한다. | 정기납부도 같은 기간을 사용하고 실제 날짜 범위를 표시한다. |

본 문서는 정기납부의 기본 화면과 계좌별 처리에 대해 기존 디자인 PRD의 항목 중심 배치 제안을 대체한다. 기존 급여 주기, 카드 청구 계산, 생활비 중복 집계 방지 규칙은 유지한다.

## 3. 범위와 제품 결정

### 이번 개편에 포함

- 이번 주기 총 지출예정액, 남은 이체액, 계좌별 완료 상태.
- 계좌별 고정지출·카드대금 통합 집계와 접기/펼치기.
- 계좌번호 및 이체 금액 복사.
- 계좌 단위 납부처리, 하위 항목 자동 완료, 묶음 취소.
- 추정 카드대금·계좌 미연결·처리 후 금액 변경 안내.
- 급여 설정과 정기납부의 집계 및 상태 공유.
- 자금을 옮긴 상태와 실제 납부한 상태의 구분.

### 이번 개편에 포함하지 않음

- 은행 송금 실행, 은행 잔액 및 자동이체 결과 자동 조회.
- 카드 이용기간·청구 산식의 전면 변경.
- 수입·생활비·저축 관리 화면의 전면 개편.
- 여러 계좌를 한 번에 실제 송금하거나 전체 납부처리하는 기능.

### 기간 기준

사용자가 말하는 ‘이번 달’은 기존 앱과 동일하게 **선택한 급여 주기**로 해석한다. 예를 들어 급여일이 10일이면 2026년 9월 주기는 9/10~10/9다. 화면에는 `이번 주기 총 지출예정액`과 날짜 범위를 함께 표시한다. 달력 월로 몰래 바꾸거나 카드 사용월 전체를 이번 주기 출금으로 더하지 않는다.

## 4. 화면 구성

```text
정기납부                       [관리 ⋯]
2026년 9월 주기 · 9/10~10/9

이번 주기 총 지출예정액       2,100,000원
남은 이체액                  1,900,000원
처리할 계좌 2개 · 납부 완료 0개

생활비 통장 · 국민                 [펼치기]
이번 주기 납부액              1,300,000원
보낼 금액                    1,100,000원
고정지출 2건 · 카드대금 1건
[계좌번호 복사] [금액 복사] [처리하기]

주거비 통장 · 신한                 [펼치기]
이번 주기 납부액                800,000원
보낼 금액                      800,000원
고정지출 1건
[계좌번호 복사] [금액 복사] [처리하기]

[완료한 계좌 0개]
[정기 수입] [전체 항목 관리]
```

예시는 생활비 통장의 미리 확보한 금액 20만 원을 사용자가 확인한 경우다. 카드대금이 추정이면 해당 금액 옆에 `추정 포함`을 표시한다.

### 첫 화면 원칙

- 가장 큰 숫자는 총 지출예정액, 각 계좌의 가장 큰 숫자는 보낼 금액이다.
- 계좌는 기본적으로 접힌 상태다. 항목 수가 늘어나도 기본 화면의 행 수는 계좌 수에 비례한다.
- 계좌 요약에는 별칭, 은행, 납부액, 보낼 금액, 연결 항목 수, 처리 상태만 표시한다.
- 금액·계좌 미확인 묶음 → 처리할 계좌 → 완료한 계좌 순서로 배치한다. 같은 상태에서는 계좌 순서를 유지해 처리 중 목록이 갑자기 움직이지 않게 한다.
- 완료 계좌는 하단 접힌 영역으로 이동한다. 다음 미완료 계좌에 초점을 유지한다.
- 수입 목록, 검색·필터, 원본 새로 불러오기, 제외 항목 설명은 보조 영역으로 이동한다.
- 문제가 없으면 긴 설명문이나 주의 배너를 기본 화면에 표시하지 않는다.

### 계좌를 펼쳤을 때

| 연결 항목 | 예정일 | 금액 | 상태 |
|---|---|---:|---|
| 보험료 | 9/15 | 200,000원 | 예정 |
| 통신비 | 9/20 | 100,000원 | 예정 |
| 삼성카드 대금 | 9/25 | 1,000,000원 | 확정 · 예정 |

- 상세에서도 카드대금은 동일한 납부 구성 목록에 들어간다. 독립 카드 납부 체크박스나 별도 완료 버튼은 없다.
- 카드 청구액 수정과 이용기간 확인은 카드 행의 상세에서 제공한다.
- 카드로 결제되는 구독·보험 등은 `카드대금에 포함된 고정지출` 안에 참고로 표시한다. 이를 계좌 직접출금 금액에 다시 합산하지 않는다.
- 카드 이용기간에 실제로 포함되는 항목만 해당 청구서의 구성으로 표시한다. 다음 청구 대상은 `다음 청구 예정`으로 구분한다.
- 기존 월별 금액 수정·이번 주기 제외 기능은 상세에서 유지한다.

## 5. 금액과 계좌 연결 규칙

### 5.1 총 지출예정액

```text
총 지출예정액
  = 이번 주기 계좌 직접 고정지출
  + 이번 주기 결제일이 도래하는 카드대금
  + 계좌 외 납부가 필요한 정기지출
```

- 총액은 완료분을 포함한 주기 전체 규모다. 납부처리했다고 총액이 줄지 않는다.
- 제외한 일정, 자동 카드대금으로 대체된 수동 카드대금은 합계에서 제외한다.
- 카드로 결제한 고정비와 카드대금을 중복 합산하지 않는다.
- 카드 확정 청구액을 우선한다. 확정액이 없으면 기존 추정 산식을 사용하고 추정 포함 사실을 표시한다.
- 실제 납부 완료 금액 → 저장된 해당 회차 금액 → 기존 계획 규칙에 따른 예상 금액 순서로 사용한다. 원본 기본금액으로 월별 수정액을 덮지 않는다.
- 고정 수입, 일반 생활비, 내 계좌 사이 이체는 이 총액에 포함하지 않는다.
- 계좌 미연결 금액도 총액에는 포함한다. 금액 자체를 모르면 `확인된 금액 기준 · 미확인 N건`을 표시해 완전한 총액으로 보이지 않게 한다.

### 5.2 계좌별 납부액과 보낼 금액

```text
계좌별 납부액 = 연결된 직접 고정지출 + 연결 카드대금
계좌별 미납부액 = 계좌별 납부액 중 아직 실제 납부하지 않은 금액
보낼 금액 = max(0, 계좌별 미납부액 - 현재 이 납부에 확보해 둔 금액)
남은 이체액 = 이체 대상이 확인된 계좌들의 보낼 금액 합계
```

- `확보해 둔 금액` 기본값은 0원이다. 사용자가 계좌 상세에서 이번 납부에 쓸 수 있는 금액을 확인·입력한다.
- 잔액 스냅샷은 기준일과 함께 참고로 표시한다. 다른 생활비가 섞일 수 있으므로 자동 차감하지 않는다.
- 확보액은 이번 주기·해당 계좌에만 적용한다. 납부로 사용한 금액은 확보액에서도 함께 소진해 이중 차감을 방지한다.
- 이미 이체 완료한 금액은 확보액에 반영하므로 다시 방문해도 같은 돈을 보내라고 하지 않는다.
- 지급 계좌가 급여 계좌 자체라면 `이체 없이 이 계좌에 확보`로 표시한다. 이때도 납부액은 총액에 포함하고, 확보 여부를 확인하기 전에는 완료로 간주하지 않는다.
- 계좌 미연결·현금 납부액은 `별도 확인 N원`으로 표시한다. 남은 이체액에 빠졌다는 이유로 모든 준비가 끝났다고 안내하지 않는다.

### 5.3 연결 관계

- 직접 고정지출은 해당 월 일정에 저장된 계좌를 우선한다. 값이 없는 기존 일정만 원본의 계좌를 보완적으로 사용한다. 명시적으로 연결을 해제한 값은 원본으로 되살리지 않는다.
- 카드대금은 카드에 설정된 결제계좌로 묶는다. 같은 계좌에 카드가 여러 장이면 모두 포함한다.
- `내 출금 계좌`와 `수취인 계좌`를 구분한다. 월세 수취인에게 직접 보내는 금액은 `직접 송금` 묶음으로 표시하며, 내 납부 통장에 채울 금액과 중복 계산하지 않는다.
- 기존 은행명·계좌번호만으로 두 계좌의 역할을 확정할 수 없으면 `계좌 확인 필요`로 둔다. 이름이 비슷하다는 이유로 자동 병합하지 않는다.
- 체크카드는 별도 신용카드 청구를 생성하지 않으며, 기존 실제 출금 규칙에 따라 한 번만 포함한다.

## 6. 계좌 단위 처리

### 6.1 기본 흐름

1. 사용자가 계좌별 보낼 금액을 확인하고 계좌번호·금액을 복사한다.
2. 은행 앱에서 이체 또는 납부를 진행한다.
3. 해당 계좌의 `처리하기`를 누른다.
4. 하단 시트에서 계좌, 처리 금액, 고정지출 N건·카드대금 N건을 확인한다. 정상 항목은 모두 포함된 상태다.
5. 처리 종류에 따라 `이체 완료` 또는 `납부처리`를 선택한다. 내 통장으로 자금을 옮기는 계좌는 이체 완료를 기본으로 제시하고, 직접 송금은 납부처리를 기본으로 제시한다.
6. 결과와 실행 취소를 표시하고, 계좌 및 상위 요약을 함께 갱신한다.

이체 준비와 실제 납부를 구분하는 이유는 급여일에 납부 통장을 채웠어도 카드 결제일이 아직 오지 않을 수 있기 때문이다. 추가적인 카드별 수동 체크는 두 흐름 모두 요구하지 않는다.

### 6.2 납부처리 — 요청한 일괄 완료 동작

**계좌에서 납부처리하면 선택 주기의 해당 계좌에 연결된 미납부 고정지출과 카드대금이 모두 자동으로 납부 완료된다.**

- 처리 시트에서 실제 납부 완료 사실을 사용자가 확인한다. 앱이 은행 출금을 검증한 것으로 표현하지 않는다.
- 기존 완료 항목과 이번 주기 제외 항목은 처리 대상에서 빠진다.
- 직접 계좌 고정지출은 해당 회차를 완료로 바꾸고 연결 거래를 기록한다.
- 카드대금은 카드별 해당 결제분의 납부 상태와 정산 거래를 함께 기록한다. 카드별 추가 클릭은 없다.
- 여러 날짜에 실제 납부한 내역이면 상세에서 날짜를 조정할 수 있다. 실제 납부일을 사용하며 미래 예정일을 실제 출금일로 자동 기록하지 않는다.
- 카드 사용 거래나 카드로 결제한 고정비의 소비 기록을 다시 만들지 않는다. 청구서 납부와 카드 사용 회차 완료는 서로 다른 사실이다.
- 카드대금의 `별도 지출 포함 여부` 설정은 만들지 않는다. 내부 정산 구분은 소비 중복을 막기 위해 유지한다.
- 카드·계좌 관리 화면의 같은 결제분 상태도 즉시 반영한다. 다른 화면의 수정도 같은 저장 경로를 이용한다.

### 6.3 이체 완료 — 아직 출금 전인 경우

- 내 납부 계좌에 돈을 옮겼다면 계좌와 그 아래 모든 대상 항목에 `이체 준비 완료`를 함께 표시한다.
- 실제 납부 상태는 예정으로 유지한다. 예: `이체 준비 완료 · 9/25 출금 예정`.
- 이체 완료만으로 고정지출 거래나 카드 정산 거래를 만들지 않는다. 내 계좌 이동을 기록한다면 `transfer`로만 기록하며 소비 합계에서 제외한다.
- 나중에 계좌 단위 납부처리할 수 있으며, 이때도 카드별 체크는 필요 없다.
- 향후 은행 연동이 생기더라도 자금 확보와 실제 출금 상태를 같은 값으로 합치지 않는다.

### 6.4 일부 처리와 예외

- 정상적인 급여일 흐름은 계좌 전체 처리다. 항목별 선택 UI는 `일부만 처리`를 펼칠 때만 제공한다.
- 일부만 실제 납부했다면 선택 항목만 완료하고 계좌에는 `일부 납부 · 남은 N원`을 표시한다.
- 카드대금의 개별 완료 버튼은 없지만, 일부 처리 상세에서 이번 묶음 대상에 포함할지는 조정할 수 있다.
- 금액이나 계좌가 미확인인 항목이 있으면 전체 납부처리를 막고 이유를 표시한다. 확인된 항목만 처리하는 것은 명시적인 일부 처리로 제공한다.
- 다른 주기 일정이나 같은 계좌의 일반 거래까지 처리하지 않는다.

## 7. 상태 변경, 실패와 취소

| 상황 | 요구 동작 |
|---|---|
| 처리 버튼 연속 탭 / 재접속 후 재시도 | 같은 회차와 카드 결제분에 거래를 중복 생성하지 않는다. |
| 여러 항목 중 저장 실패 | 계좌 전체 완료를 표시하지 않는다. 묶음 전체 저장을 우선하고, 재시도해도 중복되지 않게 한다. |
| 오프라인 | `동기화 대기`를 표시한다. 다른 기기에도 저장됐다는 성공 메시지는 표시하지 않는다. |
| 납부처리 취소 | 해당 처리 묶음이 만든 상태·거래만 되돌린다. 이전에 별도로 납부된 항목은 유지한다. |
| 이체 완료 취소 | 해당 묶음의 확보액과 준비 상태만 되돌린다. 실제 납부 기록은 건드리지 않는다. |
| 완료 후 거래를 별도 수정 | 수정한 기록을 취소 동작으로 덮지 않고 충돌 항목을 안내한다. |
| 카드 추정액이 변경 | 이체 준비 단계에서는 차액을 다시 계산해 `추가 이체 필요`를 표시한다. 실제 납부 완료 금액은 자동 변경하지 않는다. |
| 계좌 연결 변경 | 미처리 계획은 새 계좌로 이동한다. 기존 이체·납부 기록의 당시 계좌는 보존한다. 이미 확보한 돈은 자동으로 새 계좌에 옮겨졌다고 간주하지 않는다. |
| 처리 후 신규 고정지출 추가 | 새 항목만 미처리로 나타난다. 기존 계좌 완료 표시를 유지한 채 누락시키지 않는다. |
| 다음 급여 주기로 이동 | 이전 주기의 처리 상태와 확보액을 새 주기에 자동 승계하지 않는다. |

확정 0원 카드대금은 `납부 없음`으로 표시하고 0원 거래를 생성하지 않는다. 사용 기록이 없어 추정 0원인 경우는 `금액 확인 필요`로 구분한다.

## 8. 데이터 및 구현 요구사항

아래는 구현 방향이며 실제 타입명은 구현 시 조정할 수 있다.

- 계좌별 계획은 공통 집계 함수 하나에서 만든다. 정기납부, 급여 설정, 상단 합계가 동일한 입력·제외 규칙을 사용한다.
- 정기 회차는 `occurrenceKey`, 카드 청구는 카드 ID와 실제 결제분 식별자로 연결한다. 급여 주기 라벨과 카드 결제월이 항상 같다고 가정하지 않는다.
- 처리 묶음에는 주기, 계좌, 처리 종류, 포함 항목 ID, 처리 당시 금액·계좌·납부일, 이전 상태, 생성 거래 ID, 처리 시각, 저장 상태를 보존한다.
- 자금 확보 기록은 실제 납부 상태와 분리한다. 계좌 상태를 사용자가 별도로 중복 체크하게 만들지 않고 하위 항목 및 처리 기록으로 계산한다.
- 묶음 저장과 취소는 로컬·서버·재시도 경로를 함께 설계한다. 기존 항목별 함수의 단순 순차 호출만으로 전체 성공을 판단하지 않는다.
- 처리 직전 최신 데이터를 다시 검증한다. 화면에 표시한 뒤 금액·계좌가 바뀌었으면 바뀐 계획을 보여주고 이전 금액으로 자동 처리하지 않는다.
- 기존 완료 상태, 월별 수정액, 제외 일정, 삭제된 원본의 보존 일정은 유지한다. 개편을 위해 과거 거래를 일괄 재생성하지 않는다.
- 생활비 기준금액 확정 이후의 계획 변경은 기존 재확정 흐름을 따른다. 이 화면 개편 때문에 확정된 생활비를 몰래 바꾸지 않는다.

## 10. 출시 순서와 성공 기준

1. 공통 계좌 집계와 예외 규칙을 먼저 확정하고, 기존 완료·제외·월별 수정 데이터를 포함한 사례로 금액을 검증한다.
2. 계좌 중심 기본 화면, 상세, 복사 기능을 적용한다.
3. 자금 확보와 계좌 일괄 납부·취소·재시도를 구현하고 급여 설정에 연결한다.
4. 금액 경계·카드 중복·부분 완료·실패 복구 테스트와 모바일 실제 조작을 통과한 뒤 함께 출시한다.

출시 성공 기준:

- 첫 화면에서 총액과 각 계좌의 보낼 금액을 개별 항목 합산 없이 확인할 수 있다.
- 계좌 구성 확인은 한 번 펼치기로 가능하다.
- 정상 계좌의 전체 납부는 계좌 진입 후 처리 종류 확인까지 두 번의 조작으로 끝난다.
- 처리 조작 횟수는 고정지출·카드 개수가 아니라 처리할 계좌 수에 비례한다.
- 5명의 과업 테스트 중 4명 이상이 도움 없이 총액 확인 → 계좌별 이체액 확인 → 한 계좌 일괄 처리에 성공한다.
- 수용 기준 AC-01~16을 모두 충족하고 소비 이중 계산, 완료 기록 손실, 중복 거래가 없다.

## 11. 제안에 사용한 가정

- ‘이번 달’은 기존 앱의 급여 주기를 유지한다.
- 은행 잔액 전체보다 사용자가 확인한 납부용 확보액이 이체 필요액 계산에 적합하다.
- 사용자의 ‘납부처리’ 요청은 계좌에 연결된 대상의 일괄 완료로 구현한다. 다만 급여일에 돈을 옮기기만 한 경우에도 쓸 수 있도록 이체 준비 완료를 별도로 제공한다.
- 내 납부 계좌에 돈을 채우는 방식과 수취인에게 직접 송금하는 방식이 모두 존재할 수 있다. 기존 데이터의 계좌 역할이 불명확하면 연결 확인으로 해소한다.
