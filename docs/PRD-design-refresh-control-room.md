# 지출브레이크 디자인 개선 PRD — 브레이크 컨트롤룸

작성일: 2026-08-21  
상태: 제안  
대상: React 19 + Vite + Tailwind CSS 4 + Capacitor Android 앱  
참조: `landing-page-guide-v2`, `PRD-usability-improvements.md`, 현재 `main` (`96f3b02`)

## 1. 요약

지출브레이크의 핵심 가치는 거래를 많이 보여주는 것이 아니라 **지금 안전하게 쓸 수 있는 돈과 그 이유를 즉시 알려주는 것**이다. 현재 앱은 기능과 계산 모델은 충분하지만, 화면마다 비슷한 어두운 카드·작은 글자·여러 강조색이 반복되어 핵심 수치와 다음 행동의 우선순위가 약하다.

이번 개선은 앱 전체를 하나의 **브레이크 컨트롤룸**으로 재구성한다. 첫 화면에서 사용자는 3초 안에 다음 세 가지를 이해해야 한다.

1. 오늘 얼마까지 써도 안전한가?
2. 다음 급여일까지 무엇이 빠져나가는가?
3. 지금 해야 할 가장 중요한 행동은 무엇인가?

디자인은 짙은 탄소색 바탕, 따뜻한 종이색 텍스트, 브레이크 레드와 안전 그린을 사용하는 **편집형 금융 계기판** 한 방향으로 통일한다. 일반적인 핀테크 앱의 보라색 그라데이션, 동일한 둥근 카드 격자, 장식용 아이콘 남용은 제거한다.

## 2. 문제 정의

### 2.1 현재 소스에서 확인한 문제

| 문제 | 근거 | 사용자 영향 |
|---|---|---|
| 모든 정보가 비슷한 카드로 보임 | 컴포넌트에 `rounded-xl/2xl/3xl` 사용이 약 290회 | 무엇이 가장 중요한지 첫눈에 구분하기 어렵다. |
| 작은 보조 문구가 많음 | `text-[10px]`, `text-[11px]` 사용 27회 | 모바일에서 설명과 상태 배지를 읽기 어렵다. |
| 강조색의 의미가 화면마다 달라짐 | rose, amber, emerald, indigo, purple, cyan 계열이 혼재 | 색만 보고 상태나 행동을 예측하기 어렵다. |
| 장식형 그라데이션이 브랜드보다 앞섬 | 그라데이션 사용 14회, 로고와 CTA에도 복수 색상 사용 | ‘브레이크’라는 제품 정체성이 흐려진다. |
| 홈의 정보 밀도가 높음 | 급여 루틴, 기준금액 변경, 핵심 요약, 카드대금, 예측, 위험 카테고리, 정기 일정, 퀵등록이 연속 배치 | 핵심 수치를 찾기 위해 스크롤하고 문장을 읽어야 한다. |
| AI 입력 방식이 한 화면에 과밀함 | GPT 라이브, Gemini 음성, AI 문장, 영수증, 수동 입력 5개 모드 | 신규 사용자가 어떤 입력 방식을 선택해야 할지 판단하기 어렵다. |
| 분석 화면이 차트 중심 | AI 리포트와 여러 그래프가 같은 시각 무게로 배치 | “그래서 지금 무엇을 해야 하는가”가 차트 뒤로 밀린다. |
| 데스크톱 폭이 넓지만 정보 구조는 모바일 카드의 확대판 | 앱 셸 `max-w-6xl`, 다수 화면은 단순 그리드 전환 | 큰 화면에서 공간은 늘지만 판단 속도는 개선되지 않는다. |

### 2.2 해결 원칙

- **한 화면, 한 판단:** 화면 최상단에는 가장 중요한 질문 하나와 답 하나만 둔다.
- **금액 우선, 설명 후순위:** 금액·상태·날짜를 먼저 보여주고 계산 설명은 펼침 영역으로 이동한다.
- **색은 의미로만 사용:** 안전, 주의, 정지, 정보의 네 역할을 고정한다.
- **기록과 판단을 분리:** 거래 등록은 빠르게, 분석은 원인과 행동 중심으로 설계한다.
- **진짜 데이터만 신뢰 요소로 사용:** 이용자 수, 후기, 절약 성과는 검증된 자료가 있을 때만 노출한다.
- **모바일이 기준:** Android 세로 화면에서 완결된 뒤 태블릿·데스크톱으로 확장한다.

## 3. 목표와 비목표

### 3.1 목표

- 앱 실행 후 3초 안에 ‘오늘 안전 금액’과 현재 상태를 이해하게 한다.
- 주요 거래 등록을 10초 안에 완료하게 한다.
- 핵심 행동 CTA를 화면마다 하나로 제한해 선택 피로를 줄인다.
- 홈 첫 뷰포트에 안전 금액, 상태, 다음 출금, 거래 등록 진입점을 노출한다.
- 카드 사용액과 카드대금, 계좌 고정 이체의 차이를 시각적으로 명확히 한다.
- 360px 폭부터 데스크톱까지 정보가 잘리거나 과도하게 늘어나지 않게 한다.
- WCAG 2.2 AA 수준의 대비, 포커스, 터치 영역을 확보한다.

### 3.2 비목표

- 급여 주기·카드 정산·고정비 계산 로직 변경
- 은행 및 카드사 자동 연동
- 검증되지 않은 후기, 평점, 사용자 수 생성
- React/Vite를 Next.js로 이전
- 모든 화면을 한 번에 재작성하는 빅뱅 릴리스
- 장식만 바꾸고 정보 구조는 그대로 두는 테마 교체

## 5. 단일 디자인 방향: 브레이크 컨트롤룸

### 5.1 콘셉트

교통 신호와 차량 계기판의 즉시성에, 금융 명세서의 정돈된 숫자 표현을 결합한다. 자동차 UI를 그대로 흉내 내지 않고, **브레이크 라인**, **위험 구간**, **잔여 거리**라는 시각 언어만 가져온다.

핵심 인상은 다음 세 단어다.

- 단호함
- 정확함
- 안심

### 5.2 타이포그래피

| 용도 | 제안 | 규칙 |
|---|---|---|
| 브랜드·화면 제목 | Gmarket Sans Bold | 짧고 강한 제목에만 사용한다. |
| 본문·버튼·라벨 | SUIT Variable | 모바일 한글 가독성과 숫자 정렬을 우선한다. |
| 금액 | SUIT Variable, `font-variant-numeric: tabular-nums` | 모든 금액의 자리 폭을 고정한다. |

- 본문 최소 14px, 보조 정보 최소 12px로 제한한다.
- 핵심 금액은 모바일 40~48px, 데스크톱 56~64px 범위의 유동 크기를 사용한다.
- 웹폰트는 필요한 굵기와 한글 서브셋만 자체 호스팅하고, 폰트 로딩 실패 시 레이아웃 이동이 없게 한다.

### 5.3 색상 토큰

| 토큰 | 값 | 용도 |
|---|---:|---|
| `--canvas` | `#0B0D0F` | 앱 배경 |
| `--surface-1` | `#14171A` | 주 표면 |
| `--surface-2` | `#1C2024` | 상승 표면·입력 |
| `--ink` | `#F4F1EA` | 주 텍스트 |
| `--muted` | `#A8AFB7` | 보조 텍스트 |
| `--line` | `#30363C` | 구분선 |
| `--brake` | `#FF4D3D` | 중단·초과·주 CTA |
| `--safe` | `#3DDC97` | 안전·완료 |
| `--caution` | `#F5B942` | 주의·확인 필요 |
| `--info` | `#78A9FF` | 중립 정보·카드대금 |

- 그라데이션은 기본 컴포넌트에서 사용하지 않는다.
- 빨강은 브랜드 장식이 아니라 ‘브레이크/주요 행동/위험’에만 사용한다.
- 카드대금은 `info`, 계좌 고정 이체는 중립 회색, 생활비 사용은 `brake`, 확보한 저축은 `safe`로 전 화면에서 고정한다.
- 라이트 모드는 단순 색상 반전이 아니라 따뜻한 종이색 `#F5F1E8`을 바탕으로 별도 토큰을 제공한다.

### 5.4 형태와 공간

- 주요 카드 12px, 시트·모달 20px 반경으로 반경 단계를 두 개로 제한한다.
- 같은 크기의 카드 격자를 기본 레이아웃으로 쓰지 않는다.
- 얇은 실선, 영수증형 점선, 굵은 수치로 정보 계층을 만든다.
- 데스크톱은 `상태 7 : 근거 5` 비율의 비대칭 2열을 사용한다.
- 모바일은 중요한 정보 순서대로 단일 열을 사용하고 수평 스크롤 카드 묶음을 최소화한다.

### 5.5 아이콘과 모션

- Lucide 아이콘은 동작·상태 식별에만 사용하고 제목 옆 장식 아이콘은 제거한다.
- 앱 진입 시 핵심 금액 → 브레이크 선 → 다음 행동 순으로 300ms 이내 한 번만 등장한다.
- 금액 변경은 숫자 크로스페이드, 진행 상태는 짧은 선 이동으로 표현한다.
- 무한 펄스, 과도한 스프링, 여러 카드의 개별 등장 애니메이션은 금지한다.
- `prefers-reduced-motion`에서는 모든 전환을 즉시 완료한다.

### 6.1 전역 구조

하단 내비게이션은 현재 구조를 유지한다.

- 홈

- 중앙 거래 등록
- 분석

## 7. 화면별 요구사항

### P0-1. 홈 히어로 재구성

- 기존 요약 카드들을 하나의 `SafetyHero`로 통합한다.
- 제목은 “오늘 안전하게 쓸 수 있는 돈”, 주 수치는 일일 안전 금액으로 고정한다.
- 상태는 `안전 / 주의 / 정지` 세 단계로 단순화하되 기존 계산 단계와 매핑한다.
- 브레이크 선에는 사용률, 오늘 위치, 주기 종료 위치를 함께 표시한다.
- 주 CTA는 상황에 따라 하나만 노출한다.
  - 정상: `지출 기록하기`
  - 급여일 미확정: `이번 주기 확정하기`
  - 데이터 보정 필요: `확인할 항목 보기`
- 상세 계산, 기준금액 변경, 장문 설명은 `계산 근거` 시트로 이동한다.

**수용 기준:** 360×800 화면에서 스크롤하지 않고 안전 금액, 상태, 주 CTA, 다음 출금이 보인다.

### P0-2. 카드대금과 계좌 고정 이체 시각 분리

- 자금 흐름을 `수입 → 계좌 고정 이체 → 카드대금 → 생활비/저축` 순서로 보여준다.
- 카드 사용은 생활비 사용 시점, 카드대금은 연결 계좌 출금 시점이라는 설명을 정보 시트에 고정한다.
- 카드대금 행에는 사용기간, 결제일, 출금 계좌, 확정/추정 상태를 한 묶음으로 표시한다.
- 동일 거래가 두 번 합산된 것처럼 보이는 합계 배치나 문구를 금지한다.
- 추정 금액은 `약`, `예상`, 점선 테두리 중 두 가지 이상으로 표시한다. 색상만으로 구분하지 않는다.

**수용 기준:** 사용성 테스트 참여자 5명 중 4명 이상이 카드 사용액과 카드대금의 차이를 설명할 수 있다.

### P0-3. 거래 등록 구조 단순화

- 중앙 버튼을 누르면 먼저 `빠른 등록` 화면을 연다.
- 첫 줄에는 마지막 사용 방식 또는 사용자 지정 기본 방식 하나를 크게 표시한다.
- 보조 입력 방식은 다음처럼 그룹화한다.
  - 말하기: Gemini 음성, GPT 라이브
  - 쓰기: AI 문장, 수동 입력
  - 찍기: 영수증
- 기존 5개 탭을 동일 폭으로 한 줄에 배치하지 않는다.
- 분석 결과 확인 화면은 입력 방식과 관계없이 같은 `TransactionReview` 컴포넌트를 사용한다.
- 저장 전에는 금액, 사용처, 결제수단, 날짜를 가장 먼저 보여준다. AI 판단 이유는 펼침 영역으로 이동한다.
- 키보드가 열린 세로 화면에서도 저장 버튼을 고정 하단에 노출한다.

**수용 기준:** 최근 사용 방식으로 거래 저장까지 평균 10초 이하, 새 사용자가 입력 방식을 선택하는 데 5초 이하가 걸린다.

### P0-4. 화면 밀도와 접근성 기준선

- 본문 14px, 보조 라벨 12px 미만을 금지한다.
- 모든 버튼과 탭의 터치 영역을 최소 44×44px로 유지한다.
- 숫자·상태·CTA의 대비는 WCAG AA를 충족한다.
- 모달·시트는 제목, 포커스 트랩, ESC/뒤로가기, 닫은 뒤 포커스 복귀를 제공한다.
- 위험·안전 상태는 색과 함께 아이콘 또는 텍스트를 사용한다.
- TalkBack 읽기 순서는 시각 순서와 일치해야 한다.

**수용 기준:** 자동 접근성 검사에서 중대 위반 0건, Android TalkBack으로 거래 등록 완료가 가능하다.

### P1-1. 분석을 ‘행동 보고서’로 전환

- 화면 첫 요소를 AI 카드가 아니라 `이번 주 결론`으로 바꾼다.
- 결론은 데이터 기반 한 문장, 근거 최대 3개, 추천 행동 최대 2개로 제한한다.
- AI가 꺼져 있거나 실패해도 규칙 기반 수치 요약이 항상 노출된다.
- 차트에는 제목만 두지 말고 해석 문장을 함께 제공한다.
- 원형 차트는 정확한 비교가 필요한 경우 가로 막대로 변경한다.
- 향후 6주기 약정 지출은 가로 스크롤 카드가 아니라 주기별 누적과 원인을 읽을 수 있는 타임라인으로 표시한다.

**수용 기준:** 사용자가 차트를 직접 해석하지 않아도 가장 위험한 항목과 추천 행동을 찾을 수 있다.

### P1-2. 내역 화면 가독성과 조작 개선

- 날짜별 그룹 헤더에 일일 지출 합계를 표시한다.
- 행의 1차 정보는 사용처와 금액, 2차 정보는 시간·카테고리·결제수단으로 고정한다.
- 카드 결제, 계좌 이체, 현금은 텍스트 라벨로 표시하고 색만 사용하지 않는다.
- 검색과 기간·카테고리 필터는 하나의 필터 시트로 통합한다.
- 편집/삭제는 행 안의 상시 아이콘 대신 상세 또는 스와이프 동작에 둔다. 삭제는 실행 취소를 유지한다.

**수용 기준:** 360px 폭에서 사용처와 금액이 줄임 없이 우선 표시되고, 한 화면에 최소 5개 내역을 읽을 수 있다.

### P1-3. 정기납부 및 계좌/카드 화면 재구성

- 정기납부는 `확인 필요 → 예정 → 완료` 순서로 배치한다.
- 각 항목은 이름, 계획 금액, 날짜, 결제수단, 상태만 기본 노출한다.
- 계좌/카드 화면은 자산 등록 목록보다 `다음 카드대금 대비 잔액`을 먼저 보여준다.
- 카드별로 결제일과 사용기간을 시각적으로 연결한다.
- 등록·수정 폼의 고급 항목은 단계적으로 펼친다.

**수용 기준:** 사용자가 카드대금이 어느 계좌에서 빠지는지 두 번 이하의 탭으로 확인할 수 있다.

### P1-4. 온보딩 개선

- 온보딩은 ‘제품 설명’보다 첫 안전 금액 계산을 목표로 한다.
- 3단계 입력(월 수입/급여일 → 고정지출 → 생활비 한도)을 유지하되 각 단계에서 결과 변화를 즉시 미리 보여준다.
- 완료 화면에 첫 안전 금액, 다음 급여일, 등록된 계획을 요약한다.
- 건너뛰기는 허용하되 홈에 비차단형 재개 링크를 제공한다.
- 권한 요청은 해당 기능을 처음 실행하는 순간에만 이유를 설명한 뒤 요청한다.

**수용 기준:** 빈 데이터 사용자가 2분 안에 첫 안전 금액을 확인할 수 있다.

### P2-1. 데스크톱·태블릿 적응형 레이아웃

- 840px 이상에서는 홈을 `SafetyHero 7 : 다음 행동/출금 5`의 2열로 배치한다.
- 분석은 결론 영역을 고정 폭으로 두고 근거 차트를 넓은 열에 배치한다.
- 콘텐츠 최대 폭은 유지하되 카드 자체를 무작정 늘리지 않는다.
- 태블릿 가로 모드에서도 하단 내비게이션을 유지하고, 데스크톱 브라우저에서만 좌측 레일 전환을 검토한다.

**수용 기준:** 1440px 화면에서 주요 콘텐츠 행 길이가 과도하게 늘어나지 않고 빈 공간이 의도된 여백으로 보인다.

## 10. 콘텐츠 원칙

- “잔액”, “예산”, “사용 가능”처럼 혼동되는 말을 한 화면에서 섞지 않는다.
- 핵심 용어를 다음처럼 고정한다.
  - `오늘 안전 금액`: 오늘 추가로 써도 되는 권장 금액
  - `남은 생활비`: 현재 주기에 배정된 생활비 중 미사용 금액
  - `계좌 고정 이체`: 카드대금이 아닌 계좌 기반 고정 출금
  - `카드대금`: 이전 사용기간의 신용카드 결제 예정/확정 금액
  - `카드 사용`: 결제한 날의 생활비 사용
- 위험 문구는 비난하지 않고 상태와 다음 행동을 함께 쓴다.
  - 금지: “과소비했습니다.”
  - 권장: “현재 속도면 6일 전에 생활비가 끝납니다. 외식 한도를 4만 원 줄이면 안전선으로 돌아옵니다.”
- AI 문장은 결과를 과장하지 않고 근거 수치를 연결한다.

## 11. 성능 및 품질 요구사항

- 모바일 LCP 2.5초 이하, CLS 0.1 이하를 목표로 한다.
- 홈 핵심 수치는 폰트·AI 응답을 기다리지 않고 즉시 렌더링한다.
- 차트 라이브러리는 분석 화면에서만 지연 로딩한다.
- 공개 소개 페이지의 첫 화면 이미지는 AVIF/WebP와 명시적 크기를 사용한다.
- 애니메이션은 transform/opacity 중심으로 구현한다.
- 폰트는 `font-display: swap`과 크기 조정값으로 레이아웃 이동을 방지한다.
- 360×800, 412×915, 768×1024, 1440×900을 필수 검증 크기로 사용한다.
- Android 소프트 키보드, 제스처 내비게이션, 상태 표시줄, 화면 회전을 검증한다.

- [ ] 홈 첫 뷰포트에 핵심 4요소가 노출된다.

- [ ] 모든 터치 타깃이 44×44px 이상이다.
