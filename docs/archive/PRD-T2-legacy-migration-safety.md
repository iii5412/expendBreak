# T2. 레거시 마이그레이션 실패 처리 및 재복사 덮어쓰기 방지 PRD

- 문서 상태: 구현 완료 (2026-09-23), 수용 기준 1건 부분 충족
- 작성일: 2026-09-23
- 우선순위: P0
- 예상 규모: 0.5~1일
- 관련 문서: [개선사항 인덱스](../PRD-2026-09-23-improvements-index.md), [DEPLOYMENT.md](../DEPLOYMENT.md) §2

## 1. 배경

`ensureLegacyDataMigration`(`server.ts:464-563`)은 루트 컬렉션을 `users/{OWNER_UID}` 아래로 복사하고 개수·금액 합계를 검증한다. 하지만 모든 예외를 잡아 `skipped: true`로 바꾸고, 라우트는 `ok: true`를 돌려준다(`server.ts:556-563`, `576-577`).

결과:

1. 검증 실패(`missing`, `amount totals differ`)도 클라이언트(`storage.ts:304-308`)에는 성공으로 보여 데이터를 그대로 로드한다. `DEPLOYMENT.md`의 “검증 실패 시 클라이언트는 데이터를 로드하지 않음” 설명과 반대다.
2. 완료 마커가 기록되지 않으므로 다음 로그인에서 다시 복사한다. 복사는 `batch.set(..., { merge: false })`라서, 그사이 사용자가 고친 같은 ID 문서를 레거시 원본으로 **덮어쓴다**.

운영에는 이미 `legacy-root-v1` 마커가 있을 가능성이 높아 당장의 피해는 없을 수 있다. 그러나 새 배포 환경이나 마커 삭제 시 데이터가 손실되는 경로이므로 코드를 고친다.

## 2. 목표

1. “실행할 수 없음(Admin 미연결)”과 “실행했으나 검증 실패”를 구분한다.
2. 검증 실패는 클라이언트에 오류로 전달되고, 앱은 데이터 로드를 멈추고 안내한다.
3. 어떤 경우에도 재실행이 사용자 데이터를 덮어쓰지 않는다.

## 3. 요구사항

### R1. 결과 유형 구분

| 상황 | HTTP | 응답 | 마커 |
|---|---|---|---|
| 마커가 이미 있음 | 200 | `{ ok: true, report }` | 변경 없음 |
| 복사·검증 성공 | 200 | `{ ok: true, report }` | `legacy-root-v1` 기록 |
| Admin SDK 초기화 실패 등 실행 불가 | 200 | `{ ok: true, report: { skipped: true, reason: 'admin_db_unavailable' } }` | 없음 |
| 검증 실패 | 500 | `{ error: 'Migration failed', message, failure }` | `legacy-root-v1-failed`에 원인·시각·컬렉션별 수치 기록 |

- `ensureLegacyDataMigration`의 광역 `catch`를 제거하고, Admin 초기화 단계에서만 `skipped`를 반환한다.
- 검증 오류는 `MigrationVerificationError`로 던져 라우트에서 500으로 변환한다.

### R2. 재복사 시 덮어쓰기 금지

- 복사 시 대상 문서가 이미 있으면 건너뛴다. `batch.create()`를 쓰거나, 대상 컬렉션을 먼저 읽어 존재하는 ID를 제외한다.
- 건너뛴 문서 수를 보고서의 `skippedExisting`에 남긴다.
- 금액 합계 검증은 “원본 ID 집합 기준으로 대상에 존재하는지”만 확인한다. 이미 존재하던 문서의 금액이 사용자 수정으로 달라진 것은 실패로 보지 않는다.

### R3. 클라이언트 처리

- `ensureServerSideMigration`(`storage.ts:303-309`)은 이미 `!ok`면 예외를 던진다. 서버가 500을 제대로 반환하기만 하면 hydrate가 중단되므로, 이 예외가 흰 화면이나 일반 오류가 아니라 전용 전체 화면 안내로 이어지는지 확인·보강한다: “기존 데이터 이전 검증에 실패했습니다. 원본은 그대로 있습니다. 관리자에게 알려 주세요.”
- 안내에는 “다시 시도” 버튼만 둔다. 실패 상태에서 로컬 기본값을 만들거나 Firestore에 쓰지 않는다.
- 응답의 `skipped: true`는 현재처럼 정상 진행한다.

## 4. 수용 기준

- [x] 레거시 금액 합계가 다르도록 만든 에뮬레이터 데이터에서 `/api/migration/ensure`가 500을 반환하고 `legacy-root-v1-failed` 문서가 생긴다. (에뮬레이터 대신 인메모리 Firestore 더블로 검증)
- [ ] 같은 상황에서 앱은 대시보드를 보여 주지 않고 실패 안내를 표시한다. (부분 충족: 로컬 캐시가 없는 첫 부팅은 안내만 표시한다. 캐시가 있는 부팅은 캐시로 대시보드를 먼저 그린 뒤 검증 실패 시 안내로 바뀌므로 잠깐 보일 수 있다. 안내 화면은 컴포넌트 테스트로만 확인했고 실제 실패 데이터로 앱을 돌려 보지는 않았다)

- [x] Admin 자격 증명이 없는 개발 환경에서는 `skipped`로 정상 진행된다.
