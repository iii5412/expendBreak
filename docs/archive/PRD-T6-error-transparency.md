# T6. 오류 경계와 실패 투명성 PRD

- 문서 상태: 구현 완료 v1.1 (2026-10-01)
- 작성일: 2026-09-23
- 우선순위: P1
- 예상 규모: 0.5~1일
- 관련 문서: [개선사항 인덱스](../PRD-2026-09-23-improvements-index.md)

## 1. 배경

- `src` 전체에 React `ErrorBoundary`가 없다. 한 화면의 렌더 오류(예: 손상된 캐시 데이터)가 앱 전체를 흰 화면으로 만든다. 지연 로드되는 화면들은 `Suspense`(`App.tsx:1460`) 하나로만 감싸여 있다.
- `/api/ai/feedback`은 실패하면 고정된 문구(“외식 및 배달 횟수 1회 줄이기, 약 25,000원 절감” 등)를 실제 분석 결과처럼 200으로 반환한다(`server.ts:1566-1573`). 사용자는 가짜 조언을 자기 데이터 분석으로 오해한다.
- 가계부 앱에서 “실패를 성공처럼 보이게 하는 것”은 금액 신뢰도를 직접 해친다.

## 2. 목표

1. 한 화면의 오류가 다른 화면과 데이터 입력을 막지 않는다.
2. AI 기능 실패는 실패로 표시된다.

## 3. 요구사항

### R1. 화면 단위 오류 경계

- `src/components/ui/ErrorBoundary.tsx`를 추가한다(클래스 컴포넌트, `getDerivedStateFromError` + `componentDidCatch`).
- 배치:
  - 앱 최상위: 최후의 방어선. 안내 + “다시 불러오기” + “캐시 비우고 다시 시작”.
  - 각 탭 화면(`Dashboard`, `History`, `Analytics`, `Management`, `Accounts`, `RecurringPayment`)과 거래 입력 모달: 해당 영역만 대체 UI로 바꾸고 하단 탭은 계속 동작.
- 대체 UI 문구: “이 화면을 표시하지 못했습니다. 입력한 데이터는 안전합니다.” + “다시 시도”(경계 리셋).
- “캐시 비우고 다시 시작”은 앱 키 접두사(`brake_`, `eb_`)만 지운다. 아웃박스에 미전송 변경이 있으면 먼저 경고하고, 해당 키는 지우지 않는다.
- `componentDidCatch`는 기존 진단 런타임(`utils/diagnosticRuntime.ts`)에 오류 이름, 메시지, 컴포넌트 스택을 기록해 진단 내보내기에 포함되게 한다.

### R2. AI 피드백 실패 응답

- 서버: `catch`에서 고정 문구를 반환하지 말고 `502 { error: 'ai_feedback_failed', message: 'AI 분석을 불러오지 못했습니다.' }`를 반환한다. Gemini 키가 없으면 `503 { error: 'ai_disabled' }`.
- 클라이언트(`AnalyticsView.tsx:136` 부근): 실패 시 분석 카드 자리에 “AI 분석을 불러오지 못했습니다 · 다시 시도”를 표시한다. 이전에 성공한 캐시가 있으면 “n일 전 분석”이라는 시점 표시와 함께 보여 준다.
- 다른 AI 라우트(`classify`, `category-recommend`, `receipt`, `voice`)도 실패 시 그럴듯한 기본값을 반환하는 곳이 있는지 점검하고 같은 원칙을 적용한다.

## 4. 수용 기준

- [x] 화면에서 예외가 나면 그 영역만 대체 UI가 되고 하단 탭은 동작한다. (`App`이 탭 영역과 거래 입력 모달을 각각 `ErrorBoundary`로 감싼다. 이 저장소에는 DOM 테스트 환경이 없어 상태 전환과 대체 UI 마크업만 서버 렌더링으로 테스트했고, 실제 브라우저에서 예외를 일으켜 보지는 않았다)
- [x] 대체 UI의 “다시 시도”로 복구되며, 탭을 옮기면(`resetKey`) 자동으로 초기화된다.
- [x] 진단 내보내기에 기록된다. (`runtime.renderErrors`, 최근 10건. 오류 이름·메시지·컴포넌트 스택)
- [ ] `GEMINI_API_KEY`가 잘못된 값일 때 분석 화면이 실패 안내를 표시한다. (서버는 502 `ai_feedback_failed`, 키 없음은 503 `ai_disabled`로 바꿨다. 화면은 실패 안내와 “다시 시도”를 표시하고, 같은 주기의 이전 분석이 있으면 “n일 전” 표시와 함께 보여 준다. 개발 환경에 Google 자격 증명이 없어 인증된 요청으로 실제 호출해 보지는 못했다)
- [x] 서버 응답과 빌드 결과에 고정 조언 문구가 없다. (이미 기기에 저장된 고정 문구 캐시도 읽을 때 걸러낸다)

## 5. 구현 메모

- 최상위 경계는 `main.tsx`에서 `FeedbackProvider`까지 감싼다. “캐시 비우고 다시 시작”은 `brake_`/`eb_` 키만 지우되 로그인 세션과, 미전송 변경이 남은 `brake_firestore_outbox*`는 남긴다(`utils/cacheReset.ts`).
- 같은 원칙을 `category-recommend`에도 적용했다. 키가 없거나 실패하면 고정 추천·빈 목록 대신 503/502를 반환하고 관리 화면이 오류 토스트를 띄운다.
- `classify`는 규칙·키워드 추정을 계속 반환한다(사용자가 확인한 뒤에만 저장되므로). 대신 `reason`을 “AI가 꺼져 있어/연결에 실패해 규칙·키워드로만 추정했습니다”로 바꿔 AI 판단처럼 보이지 않게 했다.
- 영수증·음성·채팅 라우트는 이미 실패를 오류로 반환하고 있어 변경하지 않았다.
