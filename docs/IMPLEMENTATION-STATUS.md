# ExpendBreak PRD 구현 현황

기준일: 2026-08-10

이 문서는 `PRD-production-hardening.md` 중 이번 작업에서 실제로 반영한 범위와 운영 배포 전에 남은 작업을 구분한다. 현재 운영 Firestore 데이터와 배포 환경은 변경하지 않았다.

## 이번 작업에서 완료

### 1. 단일 사용자 PIN 인증과 데이터 보호

- PIN 검증을 서버로 이동하고 PBKDF2 hash만 운영 secret으로 사용한다.
- PIN 성공 시 고정 소유자 UID의 Firebase custom token을 발급한다.
- 로그인 전에는 Firestore hydrate와 실시간 구독을 시작하지 않는다.
- AI API도 같은 Firebase 소유자 토큰을 검증한다.
- 로그인 실패 지연 및 IP별 요청 제한, 30분 유휴 잠금을 적용했다.
- 잠금 시 앱 전용 로컬 캐시와 리스너를 정리한다.

### 2. 기존 운영 데이터의 비파괴 이관

- 기존 루트 컬렉션을 `users/{OWNER_UID}` 아래로 복사한다.
- 문서 ID, 문서 수, 거래 금액 합계를 검증하고 마이그레이션 보고서를 남긴다.
- 유형·카테고리 불일치 건수와 금액도 보고서에 기록한다.
- 원본 루트 데이터는 삭제하지 않으며 같은 이관을 다시 실행하지 않도록 마커를 사용한다.
- 신규 브라우저가 hydrate 전에 초기 샘플 데이터를 덮어쓰지 않도록 부팅 순서를 변경했다.

### 3. 수입·지출 및 카테고리 무결성

- 거래와 정기 항목의 기본 카테고리를 유형별 `기타`로 분리했다.
- 거래 입력, AI 확인, 거래 수정, 정기 항목에서 선택 유형과 같은 카테고리만 표시한다.
- 저장 계층과 Firestore rules에서 유형·카테고리 일치를 다시 검증한다.
- 카테고리 병합은 같은 유형끼리만 허용하며 연결 문서와 발생 건 snapshot을 함께 변경한다.
- 기존 불일치는 분석에서 반대 유형 카테고리로 섞지 않고 `분류 확인 필요`로 표시한다.
- 설정 화면에서 불일치 거래·정기 항목·고아 발생 건을 확인하고 사용자 확인 후 정리할 수 있다.
- 총 수입·총 지출은 거래 유형을 기준으로 유지하고, 카테고리 분석도 같은 유형 안에서만 집계한다.

### 4. 정기 지출 정확성

- 월말 날짜 보정, 시작·종료일, 주간/월간 주기, 주말 조정 정책을 발생 건 생성에 반영했다.
- 발생 건에 유형·카테고리·템플릿 revision snapshot을 저장한다.
- 정기 건 확정은 거래 생성과 발생 건 `posted` 변경을 Firestore transaction으로 묶었다.
- 결정적 ID를 사용해 빠른 중복 처리로 거래가 두 번 생기는 것을 막았다.
- 연결 거래 삭제 시 발생 건을 다시 확인 대기로 돌리고, 템플릿 삭제 시 미처리 발생 건은 건너뜀 처리한다.
- 근거 snapshot이나 템플릿이 없는 고아 발생 건을 예정 지출에서 제외한다.

### 5. 계좌와 일상 UX

- 계좌 잔액을 거래와 자동 연동하지 않는 수동 snapshot으로 명시했다.
- 잔액 기준일과 수정 시각을 저장하고 빠른 금액 조정 및 5초 실행 취소를 제공한다.
- PIN 로그인 후 계좌번호 전체를 표시하며 번호만 복사하거나 은행·번호·예금주를 함께 복사할 수 있다.
- 계좌/카드 삭제 전에 거래·정기 항목·카드 연결 관계를 검사한다.
- CSV를 선택 월로 제한하고 셀 quoting 및 스프레드시트 수식 주입 방지를 적용했다.
- 전체 초기화는 지정 문구를 입력해야 하며 소유자 경로만 chunk 단위로 정리한다.

### 6. AI와 운영 기반

- AI 기능을 끄면 입력 분류와 분석 API를 호출하지 않는다.
- 최초 활성화 시 동의를 받고 동의 시각을 저장한다.
- 서버에서 AI 응답의 유형, 금액, 날짜, 카테고리, 문자열 길이를 검증한다.
- 서버가 플랫폼 `PORT`를 사용하고 서버 번들을 공개 정적 디렉터리와 분리했다.
- Firestore rules를 단일 소유자 경로 기준으로 강화했다.
- 배포 순서와 롤백 절차는 `DEPLOYMENT.md`에 정리했다.

### 7. 영수증 OCR 생활 기록

- 모바일 촬영/사진 선택, 브라우저 이미지 압축과 인증된 Gemini OCR API를 추가했다.
- 사용처·총액·날짜·세금·결제정보·최대 50개 품목을 추출하고 저장 전 수정하도록 했다.
- 카드번호 형태는 OCR 원문에서 마스킹하고 마지막 네 자리만 구조화해 보관한다.
- 영수증 원본은 선택적으로 소유자 전용 Firebase Storage에 저장한다.
- 거래에 생활 태그를 기록하고 사용처·메모·태그·OCR 원문·품목명을 함께 검색한다.
- 영수증 상세 보기, 전용 필터, CSV 열과 연결 이미지 삭제를 추가했다.
- 전체 제품 범위와 후속 로드맵은 `PRD-life-ledger-expansion.md`에 정리했다.

### 8. 사용자 편의 1차 (PRD-usability-improvements.md P0)

- 거래 삭제에 상세 내역을 보여주는 확인 단계와 10초 실행 취소를 추가했다.
- 삭제는 영수증 이미지를 즉시 지우지 않고 실행 취소 창이 끝난 뒤 확정 삭제한다.
- 실행 취소 시 거래와 연결 정기 발생 건(`posted`)을 함께 복원한다.
- 공통 `FeedbackProvider`(토스트/확인 다이얼로그)와 접근성 `Modal`을 도입했다.
- 네이티브 `alert`/`confirm`/`prompt` 28개소를 전부 제거했다. 폼 오류는 인라인 메시지와 포커스 이동으로 처리한다.
- 전체 초기화는 지정 문구 입력 전까지 실행 버튼이 비활성 상태로 유지된다.
- 모달 5종에 `role="dialog"`, `aria-modal`, 포커스 트랩, ESC 닫기, 배경 스크롤 잠금, 포커스 복귀를 적용했다.
- outbox 기반 동기화 상태(`syncStatus`)를 만들어 Navbar 배지, 오프라인 배너, 미반영 목록, 전체 재시도를 제공한다.
- 거래 저장은 Firestore 반영 결과를 기다려 성공/미반영 토스트를 구분해 표시한다.
- 온라인 복귀 시 미반영 변경을 자동으로 다시 전송한다.
- 잠금 화면의 기본 PIN 안내 문구를 제거했다.
- 서버의 무조건 `0000` 통과 경로를 제거했다. `APP_PIN_HASH` 또는 `APP_ACCESS_KEY`가 설정되면 해당 값만 유효하다.

### 9. 사용자 편의 2차 (PRD-usability-improvements.md P1-1, P1-2)

- 회계 기간을 `AccountingPeriod`로 추상화했다. `monthStartDay`가 1이면 달력 월과 완전히 동일하다.
- 기간 라벨은 시작 월을 따른다. 시작일이 25일이면 `2026-07`이 7/25~8/24이다.
- 요약, 카테고리 분석, 카드 사용·정산, 정기 발생 건, CSV 내보내기, AI 음성 스냅샷이 모두 같은 기간을 사용한다.
- 시작일이 1일이 아니면 기간이 두 달력 월에 걸치므로 양쪽 달의 정기 발생 건을 생성한 뒤 기간으로 거른다.
- 월 선택기를 전역 `PeriodSelector`로 옮겨 홈·정기납부·계좌·내역·분석이 같은 기간을 본다.
- 현재 기간이 아니면 "지난/다가올 기간 조회 중" 안내와 "이번 달로" 복귀 버튼을 표시한다.
- 정기납부 탭의 자체 월 이동 컨트롤과 계좌 탭의 독립 월 상태를 전역 기준에 통합했다.
- 내역 탭 기본 필터를 현재 회계 기간으로 바꾸고 오늘/7일/30일/전체는 보조 필터로 유지했다.
- 설정에 월 시작일(1~28일) 선택을 추가했다. 변경 전 적용 범위와 새 기간 범위를 확인 화면에서 보여준다.
- 분석 탭의 일별 누적 그래프를 기간 시작일 기준으로 순회하도록 바꿨다.

### 10. 타입 검사 공백 수정

- `@types/react`와 `@types/react-dom`이 설치되어 있지 않아 `tsc --noEmit`이 컴포넌트 props를 전혀 검사하지 못하고 있었다. devDependency로 추가했다.
- 그 결과 드러난 기존 문제를 함께 고쳤다.
  - `classificationIssues`를 사용하지 않는 `RecurringPaymentView`에 전달하고, 실제로 사용하는 `ManagementView`에는 전달하지 않아 설정 화면의 분류 점검 패널이 항상 0건으로 표시되고 있었다.
  - `LiveVoicePanel`의 대화 기록 `role`이 리터럴 타입으로 좁혀지지 않았다.
  - `Navbar`의 lucide 아이콘에 넘긴 `title`이 무시되어 툴팁이 표시되지 않았다.

### 11. 사용자 편의 3차 (PRD-usability-improvements.md P1-3 ~ P1-6)

- 하단 탭을 4개(홈·내역·분석·더보기) + 중앙 작성 버튼으로 줄였다. 정기납부·계좌/카드·설정은 "더보기" 시트로 옮겼고, 그중 하나가 열려 있으면 더보기 라벨이 해당 화면 이름으로 바뀐다.
- 모든 하단 탭이 최소 44×44px를 넘고 현재 탭에 `aria-current="page"`를 부여한다.
- `env(safe-area-inset-bottom)`과 `viewport-fit=cover`를 적용해 iOS 홈 인디케이터와 겹치지 않는다.
- 공통 `AmountInput`을 만들어 금액 입력 7곳을 교체했다. 천 단위 콤마 표시, 숫자 키패드 통일, `+1만/+5만/+10만` 빠른 증감, 한글 단위 판독(`125만원`)을 제공한다.
- `type="number"`를 쓰지 않으므로 스크롤 휠로 금액이 바뀌지 않고, 붙여넣은 `24,900원`도 숫자만 취해 해석한다.
- 홈의 예시 프리셋 카드를 정기 항목이 0건이고 온보딩을 마치지 않은 경우에만 노출하도록 바꿨다.
- 하드코딩 금액 3건 생성 대신 월 수입·고정비·용돈 한도를 입력받는 3단계 온보딩 시트로 교체했다. 입력 중 여유 금액과 저축 예정액을 즉시 보여주고, 건너뛰기를 허용한다.
- 유휴 잠금 시간을 5/15/30분·1시간·사용 안 함 중에서 고를 수 있게 했다(기본 30분).
- 잠금 1분 전 경고 토스트와 "계속 사용" 연장 버튼을 추가했다.
- 거래 입력 중이던 내용을 sessionStorage에 보관하고, 다시 열 때 "이어서 작성"으로 복구할 수 있다. 저장·초기화 시 즉시 삭제한다.

### 12. 사용자 편의 4차 (PRD-usability-improvements.md P2-1 ~ P2-4)

- 남은 모달(영수증 상세)까지 공통 `Modal`로 옮겨 모달 6종 전부가 dialog 역할과 포커스 트랩을 갖춘다.
- 본문 최소 글자 크기를 12px로 올렸다(`text-[10px]`·`text-[11px]` 전량 제거).
- 보조 텍스트 색을 `text-slate-400` 이상으로 올리고, 흰 글자를 쓰는 버튼 배경을 `rose-600`으로 낮췄다. 흰 글자 + `rose-500`은 3.75:1로 AA 미달이었다.
- 아이콘 전용 버튼에 `aria-label`을, 상태·오류 메시지에 `role="alert"`/`role="status"`를 부여했다.
- 용돈 사용률 막대에 `role="progressbar"`와 값 속성을 넣었다.
- 카드 계산 방식 각주를 접힘형 도움말로 옮기고, 빈 상태에 "카드 등록하기"·"정기 항목 추가" 버튼을 붙였다.
- 내역에 현재 필터 기준 수입·지출·순액 합계를 표시한다.
- 내역 다건 선택과 카테고리 일괄 변경을 추가했다. 유형이 다른 건은 건너뛰고, 변경 후 실행 취소할 수 있다.
- 검색어와 일치하는 사용처·메모 구간을 하이라이트한다.
- `manifest.webmanifest`와 앱 아이콘(192/512/maskable/apple-touch)을 추가했다. 아이콘은 `node scripts/generate-icons.mjs`로 의존성 없이 재생성한다.
- 빌드마다 버전이 바뀌는 서비스 워커를 Vite 플러그인으로 생성한다. 코드 분할된 청크를 모두 precache하므로 오프라인에서 앱이 실제로 부팅된다.
- `/api/` 요청은 서비스 워커를 우회해 절대 캐시하지 않는다. 계정 데이터와 인증 응답이 디스크에 남지 않는다.
- 새 버전이 설치되면 자동 교체 대신 "새로고침" 안내 토스트를 띄운다.
- 설정에 홈 화면 추가 안내를 넣었다. `beforeinstallprompt`가 있으면 설치 버튼을, 없으면(iOS Safari) 수동 절차를 안내한다.

## 검증 완료

- TypeScript: `tsc --noEmit` 통과 (React 타입 설치 후 컴포넌트 props 포함)
- 회귀 테스트: 12개 파일, 59개 테스트 통과 (`syncStatus` 5개, `accountingPeriod` 11개, `amount` 5개, `lockPolicy` 5개 신규)
- 시작일 1일에서 기존 집계와 동일함을 회귀 테스트로 고정했다. 기존 `calculations.test.ts`는 수정 없이 통과한다.
- 브라우저 확인: 확인 다이얼로그의 role/aria/포커스 트랩/ESC 취소/스크롤 잠금/포커스 복귀, 토스트 실행 취소 동작, 초기화 문구 입력 전 버튼 비활성
- 브라우저 확인: 시작일 25일에서 2026-08-11이 `2026-07`(7/25~8/24) 기간으로 해석되고, 기간 이동과 "이번 달로" 복귀가 동작함

## 운영 배포 전에 반드시 수행

1. Firestore 관리 백업을 생성한다.
2. 운영 환경에 `APP_PIN_HASH`, `OWNER_UID`와 Firebase Admin 자격증명을 등록한다.
3. 앱/서버를 먼저 배포하고 최초 PIN 로그인으로 비파괴 이관을 실행한다.
4. 마이그레이션 보고서의 컬렉션 수, 거래 금액, 분류 불일치를 기존 운영 화면과 대조한다.
5. 영수증 기능 공개 전 `storage.rules`를 배포하고 비소유자 접근 거부를 확인한다.
6. 검증이 끝난 뒤에만 강화된 `firestore.rules`를 배포한다.
7. 실제 운영 Firebase 프로젝트에서 권한 거부, 교차 유형 저장 거부, 중복 정기 처리 방지를 확인한다.

## 알려진 제약: 로그인 이후의 오프라인 사용

서비스 워커 덕분에 네트워크 없이도 앱이 부팅되어 PIN 화면까지는 표시된다. 그러나 PIN 확인 이후의 부팅 순서(`initializeStorageAfterLogin`)가 `/api/migration/ensure` 호출과 Firestore hydrate를 요구하므로, 오프라인 상태에서는 로그인을 완료할 수 없고 잠금 화면으로 되돌아간다.

이는 "검증이 끝날 때까지 금융 정보를 표시하지 않는다"는 `PRD-production-hardening.md`의 의도적 결정에서 비롯된 동작이므로 임의로 완화하지 않았다. 오프라인에서도 조회·기록까지 하려면 다음을 별도로 결정해야 한다.

- 캐시된 세션이 유효할 때 마이그레이션 확인을 건너뛰고 로컬 캐시로 부팅할지 여부
- 그때 표시하는 데이터가 검증되지 않은 로컬 사본임을 어떻게 알릴지
- 로컬 캐시를 잠금 시 삭제하는 현재 정책과 어떻게 조화시킬지

오프라인에서 기록한 변경이 유실되지 않는 것은 이미 outbox와 동기화 배지로 보장된다.

## 후속 개선 범위

아래 항목은 이번 핵심 구현에 포함하지 않았으며 별도 작업이 필요하다.

- Firebase App Check 적용과 운영/검증 프로젝트 분리
- Firestore rules emulator 기반 자동 테스트
- 전체 거래 실시간 구독을 기간 쿼리와 페이지네이션으로 전환
- 모든 일반 저장 작업의 서버 확인형 UI 및 오프라인 재시도 큐
- 삭제 휴지통, 거래 삭제 실행 취소, 백업 파일에서 복원
- 한국 공휴일 달력 기반 정기일 조정
- 사용자 설정형 유휴 잠금 시간과 생체 인증 연계
- `monthStartDay`와 사용자 timezone을 모든 회계 기간 계산에 적용
- AI 리포트 캐시의 데이터 revision 기반 무효화
- `ManagementView`와 저장소 계층 분리 및 E2E 테스트 확대

## 알려진 빌드·의존성 참고

- 기능별 청크 분리 후에도 Firebase SDK 청크가 약 678 kB로 Vite의 500 kB 권고를 초과한다. 기능 오류는 아니며 추후 lazy loading 대상으로 남긴다.
- `npm audit`에는 Firebase Admin의 Google Cloud 하위 의존성에서 중간 등급 항목 6개가 남는다. 제안되는 강제 수정은 Firebase Admin의 호환성 파괴 downgrade이므로 적용하지 않았다. 운영 배포 전 최신 호환 버전을 다시 확인한다.
- Firebase Admin 자격증명이 없는 로컬 환경에서는 실제 custom token 발급과 운영 Firestore 이관까지 통합 시험할 수 없다.
- 같은 이유로 브라우저 검증은 로그인 전 데이터 차단 화면까지 완료했으며, PIN 이후 영수증 촬영·Storage 업로드 E2E는 운영 또는 Firebase emulator 자격증명 환경에서 확인해야 한다.
